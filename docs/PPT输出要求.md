# PPT 输出要求（导出PPT文档）

> 用途：**交付物「导出PPT文档」的唯一口径依据**——提示词、确定性校验、SVG 渲染、导出链路都以本文件为准。
> 配套：`docs/解决方案输出要求.md`（第一份交付物）、`docs/建设工作方案输出要求.md`（第二份交付物）、
> `docs/Word输出规范.md`（Word 版式）。三者是同一批事实的三种出口：Word 讲全，PPT 只讲"能直接讲"的那几页。
> 变更表 #141，用户原话：**「将我技能里面的 PPT Marster 集成到产品里，用户点击生成 PPT 时自动完成
> PPT 生成，默认用 B 站蓝色模版，不要封面，尾页，只用中间页，全程自动完成，保持在 5-10 页的规模。
> 突出问题、方案和价值」**。

---

## 一、形态与口径

| 项 | 要求 |
|---|---|
| 入口 | 交付物步中栏顶部「导出PPT文档」按钮（与「导出Word文档」同一行、同一套选目录流程）；`POST /api/v1/projects/:id/deliverables/export-pptx` |
| 输入 | 当前项目该口径的交付物正文（`solution` / `construction` 各自可导，body `kind` 默认 `solution`） |
| 交互 | **全自动、无人交互**：一次点击 = 模型产大纲 → 渲染 SVG → 转 pptx → 落到用户选的文件夹 |
| 页数 | **5–10 页，目标 6–8 页**（超上限截尾、不足下限保留并提示，见 §五） |
| 页面构成 | **只有中间页**：不要封面页、不要目录页、不要「谢谢 / 结束」尾页；**第一页直接进内容** |
| 叙事 | **问题 → 方案 → 价值**：开头 1–2 页讲现状与问题（读者的处境与代价），中间 3–5 页讲方案、建设内容与路径，最后 1–2 页讲价值与收益 |
| 默认模板 | 技能里的 `templates/decks/bilibili-blue`（B 站蓝色）——**只取它的设计语言，页面由我们确定性渲染**（该模板目录只有 `01_cover.svg`，且用户明确不要封面） |
| 文件名 | `<场景>解决方案.pptx` / `<场景>建设工作方案.pptx`（与 Word / Markdown 同口径，复用 `exportFileName`） |
| 失败 | **不阻断**：技能缺失 / python3 不可用 / 大纲不合法 / 转档失败，一律只回一条 `notice`、不产文件、不抛 500 |

## 二、模板令牌（照抄 `bilibili-blue/01_cover.svg`）

| 项 | 值 | 用处 |
|---|---|---|
| 画布 | **1280 × 720**（导出用 `-f ppt169`） | 每页 `viewBox="0 0 1280 720"` |
| 字体 | `Arial, "Microsoft YaHei", sans-serif` | 全篇唯一字体（**无网络字体、无 `@font-face`**） |
| 主色深蓝 | `#0D47A1` | 页眉标题、顶部主色条、表头、卡片数值 |
| 渐变另一端 | `#1565C0` | 次级深蓝（右栏头、偶数卡片顶条） |
| 浅蓝点缀 | `#90CAF9` | 页序标签、要点竖条、底纹、角标 |
| 正文深灰 | `#37474F` | 一句话要点与正文 |
| 内容页底色 | `#F5F8FC` | 整页底（封面渐变不用在内容页） |
| 卡片白 | `#FFFFFF` | 内容卡片 |
| 淡蓝描边 | `#BBDEFB` | 卡片描边与表格线 |

全部集中在 `packages/infra/src/ppt-svg.ts` 的 `PPT_COLORS` / `PPT_CANVAS` / `PPT_FONT`，渲染函数不写死颜色。

## 三、每页骨架

```
┌──────────────────────────────────────────────────────────────┐
│ ▌6px 主色条（整幅宽）                                          │
│ 页面标题（#0D47A1 / bold / 38px）        第 N 页 / 共 M 页（#90CAF9 / 19px）│
│ ▍一句话要点（#37474F / 21px，左侧 4px 浅蓝竖条）                 │
│                                                              │
│                        正文区（按布局）                        │
│                                                              │
│                ～～～ 三条极淡波纹（主色，0.15 / 0.1 / 0.06）    │
│ 场景通 · <场景名>（#90CAF9 / 14px）                             │
└──────────────────────────────────────────────────────────────┘
```

- 标题 ≤ 20 字、一句话要点 ≤ 40 字（超了由领域层截断，不换行溢出）；
- 底部波纹照 `01_cover.svg` 的三条 `stroke-opacity` 写法，描边换成本页主色（浅底上白线看不见）；
- 角标与页眉文字由渲染层生成，**模型不产页序、不产场景名**。

### 硬约束（ppt-master 原生导出模式敏感）

1. 所有文本 **XML 转义**（`& < > " '`）；
2. **不用** `dominant-baseline`（PPT 里对不齐，用显式 `y` 基线）；
3. **不用** `<foreignObject>`、**不用** CSS `@font-face`、**不用**网络字体与远程图片（示意图由图形拼出来）；
4. 每个成组的块带 `<g id="…">`（导出动画按 id 分组）：`hd` / `takeaway` / `body` / `bullet-N` / `col-N` / `card-N` / `figure` / `table` / `row-N` / `deco` / `footer`；
5. 文字按**估算宽度**换行（全角 1em、半角 0.52em），换行与"不溢出画布"的判据共用同一把尺（`estimateTextWidth`）；
6. **只有内容页**：`svg_output/` 里 `01_page.svg` 就是第一张内容页。

## 四、五种布局

`layout` 取值只有这五个（别的取值按「要点」处理）：

| 布局 | 用什么字段 | 数量与限额 | 排布 |
|---|---|---|---|
| `要点` | `bullets` | 3–5 条，每条 ≤ 40 字 | 一行一张白卡片 + 左侧浅蓝竖条，最多两行文字 |
| `双栏对比` | `columns` | **恰好 2 组**，`head` ≤ 12 字，每组 ≤ 3 条、每条 ≤ 40 字 | 两栏并排（左 `#0D47A1`、右 `#1565C0` 栏头），栏内条目带浅蓝方点 |
| `数据卡片` | `cards` | 3–4 张，`value` ≤ 8 字、`label` ≤ 14 字 | 一行均分卡片，数值居中加粗主色，说明在下方 |
| `图文说明` | `bullets` | 3–5 条，每条 ≤ 40 字 | 左侧说明卡片 + 右侧**确定性画出来的层叠示意图**（不含文字、不引用任何图片） |
| `表格` | `table` | `head` ≤ 5 列（≥2 列）、`rows` ≤ 6 行，表头 ≤ 8 字、单元格 ≤ 20 字 | 主色表头 + 交替底色数据行，列宽按内容比例分配后拉满内容宽 |

**版式回落**（内容撑不起版式时降级到「要点」，绝不产空版式）：双栏不足 2 栏 → 按要点排它那一栏的条目；
数据卡片不足 3 张 → 按要点排（`value：label`）；表格页没有合规表格 → 按要点排。

## 五、确定性校验与兜底（`packages/domain/src/ppt-outline.ts`）

`parsePptOutline(text)` 是**唯一入口**，逐条判定（判定留在确定性层，模型只产内容）：

| 情形 | 处理 |
|---|---|
| 没有 JSON / 不是 JSON / 缺 `pages` / 一页可用都没有 | **明确失败值**：`outline: null` + `error`（调用方重试一次，仍失败 → `notice` + 不产文件） |
| 页数 > 10 | 截掉尾部页面，`dropped` 计数并提示 |
| 页数 < 5 | 先按「重试一次」再判（见 §六）；重试后仍不足则**保留**（无法凭空造页），记提示「少于 5 页下限」 |
| 页面不是对象 / 没有标题 / 内容为空 | 丢这一页（`dropped`），其余页照常 |
| 缺 `layout` 或取值不认识 | 按「要点」处理（内容比版式重要） |
| 标题 / 要点超字数、条数超上限 | **截断**（`trimmed` 计数）；截断不许把一页删空 |
| 标题或一句话要点命中禁用词 | 丢整页（页级问题只能丢页） |
| 要点 / 栏内条目 / 卡片 / 表格行命中禁用词 | 擦掉该条（`scrubbed` 计数），页保留 |
| 命中禁用词的表头 | 该表作废 → 按「要点」排（内容靠 `bullets` 保留） |

**禁用词三类**（`PPT_BANNED_PATTERNS`，与《建设工作方案输出要求》§五、§六同口径）：

1. **占位**：待客户提供 / 待补齐 / 待现场勘查 / 待确认 / 暂缺 / 未提供 / TBD；
2. **决策建议**：建议先 / 建议采用 / 建议采购 / 推荐采用 / 推荐方案 / 值得投入 / 应当优先 / 不建议 / 可以决定；
3. **内部痕迹**：来源：/ 出处：/ 摘自：/ 参见：/ `表X-X` / `ingest-*` / 证据级 / 权威性 / 核实结论 / 信息完整度 / 信息缺口。

> **数字不许编造**由**提示词侧**硬约束（「只用报告正文里出现过的数字，金额/台数/比例一律不许新造」）：
> 检测"这个数字是不是新造的"要与正文逐句比对，误伤率高（如「八个环节」写成「8 个环节」），
> 故不进确定性层——与《建设工作方案输出要求》§8.1 的既有取舍一致。确定性层挡的是**禁词与形状**。

## 六、大纲怎么来（提示词与调用）

- **一次模型调用**产出全部页面（`apps/server/src/ppt-prompt.ts`）；**解析失败或页数不足 5 页下限重试一次**
  （更短的提示，只重复格式与页面口径，含 5–10 页与无封面尾页）——重试仍失败才回 `notice`，重试仍不足 5 页则照常导出并在 `notice` 里说明；
- 输出**只有 JSON**：不要解释、不要 Markdown 围栏、不要前后缀——直接 `JSON.parse`；
- JSON 形状（与契约 `PptPage` 一一对应）：

```json
{"pages":[{"layout":"要点|双栏对比|数据卡片|图文说明|表格","title":"…","takeaway":"…",
"bullets":["…"],"columns":[{"head":"…","bullets":["…"]}],"cards":[{"value":"…","label":"…"}],
"table":{"head":["…"],"rows":[["…"]]}}]}
```

- 提示词里写死的页面口径：5–10 页 / 无封面目录尾页 / 问题→方案→价值 / 字段限额 / 五种布局怎么用 /
  数字不编造 / 禁占位与决策建议 / 不写表号来源页码 / 说人话；
- 模型调用走 **DSH 客户端**（`createSession` + `prompt`，与交付物正文生成同一条链路），
  流式期间照 `streamPrompt` 的心跳文案报"仍在写"。

## 七、导出链路

```
PPT_MASTER_DIR（默认 ~/.dsh/skills/ppt-master）
        │  ① 技能缺失 → notice「PPT 导出组件未就绪：找不到 ppt-master 技能」，不产文件
        ▼
取正文（getReport，界面所见 = 导出所得）
        │  ② 模型产大纲（1 次 + 重试 1 次）→ parsePptOutline 校验
        ▼
临时项目目录 os.tmpdir()/scene-ppt-<场景 id>-XXXX/
        │  ③ 逐页渲染 SVG → <项目>/svg_output/NN_page.svg
        ▼
python3 <技能>/scripts/svg_to_pptx.py <项目> -o <项目>/out.pptx --no-compat -f ppt169
        │  ④ 超时 120s；非 0 退出 → notice 带 stderr 尾巴；产物不存在 → notice
        ▼
safeWriteFileBytes(<用户目录>/<场景><口径>.pptx)
        │  ⑤ 先读后写；跑完 finally 里删掉临时目录
        ▼
{files, unchanged, notice?}（与导出 Word 完全同形）
```

- `--no-compat` **必须带**：本机没装 cairosvg，Office 兼容模式会失败；原生模式输出的形状在 PowerPoint 里可编辑；
- 技能路径可配：优先环境变量 `PPT_MASTER_DIR`，默认 `~/.dsh/skills/ppt-master`；**只读使用，不修改技能目录**；
- **`unchanged` 的实情**：转档产物（python-pptx）内含生成时间戳，同一份内容两次导出的字节通常不同 →
  实际几乎总是重写并报 `files`；`unchanged` 分支是"先读后写"的机制保障（内容真的一样时不碰文件），
  不要把它当成"不会重复写盘"的承诺；
- 用户手改过目标 pptx 时，走同一套保护：**不覆盖**，另存「(应用版 时间)」并在 `notice` 里说明。

## 八、过程可见（1–3 分钟不能干等）

PPT 导出比 Word 慢（多一次模型调用 + 逐页渲染 + 转档），进度走**现有 SSE 通道**，与结果分成两条线：

1. 前端先生成 token，订阅 `GET …/deliverables/export-pptx/events?run=<token>`；
2. 再 `POST …/deliverables/export-pptx`（body 带同一个 `run`）；
3. 服务端一路推进度：`PPT：正在梳理大纲…` → `PPT：大纲 N 页，正在渲染第 K 页…`（每页一条，不刷屏）
   → `PPT：正在转成 PPTX…` → `PPT：已导出 <文件名>`；模型长思考期间由 `streamPrompt` 的心跳补"仍在撰写"；
4. 前端把阶段文案**顶在按钮上**（不是只有「导出中…」）；失败或 `notice` 时原因原样提示、按钮恢复可点、
   **已有的产物不清空**（可以反复点）。

两边谁先到都行：通道按 token 幂等创建，订阅先到就先把 run 建起来，导出先到就由中枢重放已缓冲的进度；
没人取用的通道 15 分钟后自动收尾。

## 九、已知边界

- 不做封面 / 目录 / 尾页 / 分节页（用户明确不要）；不做图片、图表、动画（示意图由图形确定性拼出来）；
- 不做"演讲备注"（`--no-notes` 之外的备注体系不接）；
- 页数不足 5 页时不补页（无法凭空造页），只在 `notice` 里说明；
- 真跑依赖本机 ppt-master 技能与 `python3`；单测一律用假导出器（fixture），不依赖本机。
