# PPT 输出要求（导出PPT文档）

> 用途：**交付物「导出PPT文档」的唯一口径依据**——提示词、确定性校验、SVG 渲染、质量门禁、导出链路都以本文件为准。
> 配套：`docs/解决方案输出要求.md`（第一份交付物）、`docs/建设工作方案输出要求.md`（第二份交付物）、
> `docs/Word输出规范.md`（Word 版式）。三者是同一批事实的三种出口：Word 讲全，PPT 只讲"能直接讲"的那几页。
> **本文件所描述的质量水平是「导出PPT文档」的最低要求**（用户定调，变更表 #145）：字号、版面判据、
> 生成后必做的版面检查，都是**下限**，只许收紧、不许放宽（阈值落在 `PPT_MIN_QUALITY`，导出链路直接引用）。
> **大纲本身也有最低要求**（变更表 #146）：八条可判的要求写在 §八.1，阈值落在 `PPT_OUTLINE_QUALITY`。
>
> 变更表 #141（管线）与 #142（信息量与排版）。#141 用户原话：**「将我技能里面的 PPT Marster 集成到产品里，
> 用户点击生成 PPT 时自动完成 PPT 生成，默认用 B 站蓝色模版，不要封面，尾页，只用中间页，全程自动完成，
> 保持在 5-10 页的规模。突出问题、方案和价值」**。
> #142 用户原话：**「生成的质量比较差…参考一下这个PPT，用白色的底色就行，但是PPT的内容丰富程度、排版，
> 重点突出还是要高质量的」**——参考稿（用户自己的高分稿）每页 52–62 个形状、21–32 个文本块，
> 而 #141 的渲染每页只有 6 个形状：**这就是"质量差"的根因**。本版照参考稿的**结构语法**重做渲染，
> 但底色改纯白（用户明确要求），不照它的深色底。
> #145 用户原话：**「1、每页PPT最上面的蓝色窄条可以去掉 2、每页标题下面的短橙色横线可以去掉，
> 3、最小字体可以调大一点。将这个质量水平作为PPT生成的最低要求，生成后要进行版面的检查，
> 我看排版还可以稍微优化一下」**——三处视觉改动 + 生成后必做版面检查 + 把这一档质量冻结成最低要求。
> #146 用户原话：**「可以了，更新产品要求吧，不是不满足标准就报错或者什么的，而是重新从文件提取大纲，
> 优化大纲，然后再优化PPT，保证高质量。或者这么说，PPT大纲本身要有质量要求，不能只是简单的几条要求，
> 要像 B站PPT大纲生成的技能要求一样有明确的生成要求」**——**大纲**也要有像 #145 那样的可执行规范（§八.1
> 八条判据），不达标不是报错，而是**每轮重读正文 → 重新提取大纲 → 优化大纲 → 重渲染 → 再检查（最多三轮）**，
> 三轮仍未全过就取**问题最少的一轮照常导出**+ notice 如实告知（#145 的"不达标就拒绝写出"就此作废）。

## 一、形态与口径

| 项 | 要求 |
|---|---|
| 入口 | 交付物步中栏顶部「导出PPT文档」按钮（与「导出Word文档」同一行、同一套选目录流程）；`POST /api/v1/projects/:id/deliverables/export-pptx` |
| 输入 | 当前项目该口径的交付物正文（`solution` / `construction` 各自可导，body `kind` 默认 `solution`）；**每一轮都重读正文**（`getReport`，界面所见 = 导出所得） |
| 交互 | **全自动、无人交互**：一次点击 = （最多三轮）重读正文 → 产大纲 → 优化大纲 → 渲染 SVG → 版面检查 → 转 pptx → 落到用户选的文件夹 |
| 页数 | **5–10 页，目标 7 页**（超上限截尾、不足下限保留并提示，见 §六） |
| 页面构成 | **只有中间页**：不要封面页、不要目录页、不要「谢谢 / 结束」尾页；**第一页直接进内容** |
| 叙事 | **问题 → 方案 → 价值**：开头 1–2 页讲现状与问题（读者的处境与代价），中间 3–4 页讲方案、建设内容与路径，最后 1–2 页讲价值与收益 |
| **信息量** | **每页至少 12 条有效短句**（≈ 4 块 × 3–4 行；`流程阶段`/`数据卡片`/`要点清单` 这三个版式**结构上就到不了 12 条**，按各自的结构上限判：10 / 8 / 6 条，见 §八.2）；低于判定线判 `信息量不足`，重试一次并进下一轮反馈（见 §八.5）；内容必须从报告正文提炼，**数字只许来自正文**（§八.1 ④） |
| 版式 | 白底 + 浅蓝卡片分层，**每页 ≥22 个形状**（含小节标签、密排块区、底部结论带）；七种布局见 §五；**`layout` 与字段必须成套**（声明表格就必须给 `table`） |
| **字号** | **内容文字一律 ≥16px**（`PPT_MIN_FONT`）；只有页脚与页码走 15px 的元信息下限；字号上调后**换行与容量同步重算**（不再有 13/15px 的正文与格内小字） |
| **版面检查** | **渲染完必须过一遍 `checkPptDeck`**（判据见 §七）；**大纲也要过一遍 `checkPptOutlineQuality`**（§八.1）。检查结果不是"拒绝写出"，而是**下一轮的反馈**：问题清单为空就导出；三轮都没空就取问题最少的一轮照常导出 + notice 点名（§七.2） |
| 文件名 | `<场景>解决方案.pptx` / `<场景>建设工作方案.pptx`（与 Word / Markdown 同口径，复用 `exportFileName`） |
| 失败 | **不阻断**：技能缺失 / python3 不可用 / 转档失败 / 三轮大纲都没全达标（照常导出 + notice 点名），一律只回一条 `notice`、不抛 500；**只有"三轮都解析不出大纲"与"转档失败"不产文件**（没有内容 / 没有产物） |

| 页脚 | 左下 `x=80`，基线 `y=700`；**15px** `#90CAF9`（包在 `<g id="footer">` 里） | `场景通 · <场景名>`，模型不产场景名 |

### 硬约束（ppt-master 原生导出模式敏感）

1. 所有文本 **XML 转义**（`& < > " '`）；
2. **不用** `dominant-baseline`（PPT 里对不齐，用显式 `y` 基线）；
3. **不用** `<foreignObject>`、**不用** CSS `@font-face`、**不用**网络字体与远程图片（零图片：全部由形状与文字拼出来）；
4. 每个成组的块带 `<g id="…">`（导出动画按 id 分组）：`kicker`（含 `kicker-icon`）/ `hd` / `subtitle` / `chip-N` / `body` /
   `block-N`（含 `block-N-icon`）/ `col-N` / `stage-N` / `layer-N` / `card-N` / `table` / `row-N` / `th-N` /
   `item-N` / `highlight`（含 `highlight-icon`）/ `footer`；
5. 文字按**估算宽度**换行（全角 1em、半角 0.52em），换行与"不溢出画布""两块文字不相交"的判据共用同一把尺
   （`estimateTextWidth`）；容器放不下时把该条压成一行加省略号，**不出界、不压字、不裁字**；
   **断行做一次二次均衡**（#145）：行首禁则（断点落在 `，。、；：！？）》」` 上就把上一行末字一起挪下来）+
   孤字行规避（末行 <3 字就从上一行挪一个字下来，挪到 3 字为止；挪不动就不挪，宁可孤字也不溢出）+
   排到行数上限还有剩字时**末行必须用省略号交代**（不许无声丢字）；
6. **只有内容页**：`svg_output/` 里 `01_page.svg` 就是第一张内容页；
7. **图标只写占位**：`<use data-icon="tabler-outline/<名字>" x=… y=… width=… height=… fill=…/>`——
   渲染层**不读技能目录**（渲染保持确定性、单测不依赖本机技能），真图标由 ppt-master 在转档时嵌（见 §九）；
   名字必须来自 `PPT_ICONS`（清单外的名字渲染时已回落 `presentation`）；
8. **同一行内的强调用 `<tspan>`**（不带 `x`/`dy`）：真机已验证导出后是**同一段落的多个 DrawingML run**
   （各带自己的 `sz` / `b` / 颜色），**文字仍然可编辑**，不会变成图片或拆成两个文本框。

## 四、排版规范（骨架落点，变更表 #142 立、#144 升）

**总原则**：白底之上靠"卡片 + 色块 + 左侧色条"建立层次；每页一个标题、一句副题、一片密排内容区、一条结论带；
一页里的信息块**等分对齐、行距统一（30/32px）、每条内容行前有小方块**，读者从上往下扫就能读完。

| 布局 | 内容几何 | 块内排版 |

| 表格 | 表头 `h=52`，数据行 `h` **按行数摊开并整表竖直居中**（#145）：`h = clamp(56, (450−52)/行数, 行数≥3 ? 120 : 176)`，总高 ≤450；行间 1px `#D6E7F8` 横线 | 表头 `#0D47A1` 白字 16px 粗 + **每列 14×14 白图标**（`xs[i]+14`，文字 `xs[i]+36`）；**奇数行 `#F7FAFE`、偶数行白**；格内 **16px** `#37474F`（行距 24、最多两行、垂直居中，**数字 22px 粗橙强调**）；列宽按内容比例分配（最小 96px，另留 22px 图标位）后拉满 1120px |

### 四.1 颜色层次（#144）

- **一页至少 6 种颜色**（门禁硬判据，见 §七）。这条不靠内容也成立：页码 `#E3F2FD` 胶囊、
  小节标签胶囊、块头 `#E3F2FD` 横条、块卡 `#F7FAFE` 底、`#D6E7F8` 细分隔线、结论带 `#E3F2FD` 底 + `#FF9800` 竖条、
  页脚 `#90CAF9`——固定骨架自己就撑起 6–8 种；内容再叠加 `#0D47A1/#1565C0/#37474F/#5A7395`。
  （#145 去掉页顶 8px 渐变主色带后仍稳过 6 色，单测按页锁死。）
- **块侧竖条四色轮换**（`PPT_BAR_COLORS` = `#0D47A1` → `#1565C0` → `#42A5F5` → `#FF9800`，按块序号 `i % 4`）：
  同一页四块颜色不同，读者扫一眼就分得清是哪一块。
- **语义着色优先**（`pptBarColor` / `pptToneOf`，判定在确定性层）：
  块头 + 内容行命中 **问题|痛点|难点|风险|代价|不足|缺失** → 橙条（`#FF9800`）；
  命中 **价值|收益|提升|降低|达标|改善|节省** → 绿条（`#4CAF50`）；都不命中才按轮换。
  **语气只改竖条颜色，不改文字层级**（文字仍按主色 / 正文色，避免整页花掉）。
- **分隔线一律 `#D6E7F8`**：比卡片描边（`#E3F2FD`）深一档，分栏/分行才看得出来；网格的列间竖线与行间横线、
  双栏的栏间竖线、表格的行线、清单的条间线都用它。

### 四.2 图标（#144）

  领域层 `normalizePptIcon` 已把"缺 / 写错 / 带库前缀"三种情形归一，**渲染层再兜一次**（名字写错不会让整页崩，只是那处变兜底图标）。

  真图标由 ppt-master 嵌（见 §九），本仓**不读技能目录**（渲染确定、单测不依赖本机）。

### 四.3 字内强调（#144）

- **行首关键词**：一行里第一个 `：，、；` 之前**≤8 字**时，把这一段做成 `20px / bold / #0D47A1` 的 `<tspan>`，
  其余照旧 `16px / #37474F`；没有分隔符、或前缀超过 8 字 → **整行默认样式（不硬拆）**。
- **数字**：一行里**第一处**数字（含 `%` 与 个/间/倍/天/小时 等量词，如 `2 天`、`480 台`、`95%`）做成
  `22px / bold / #FF9800` 的 `<tspan>`；**一行只强调一处**，避免整页发花。
- 卡片数值 / 表头 / 阶段名 / 序号本来就是 ≥16px 粗体大字，门禁把它们一并算作"重点"；
  **每页 ≥3 处**（门禁硬判据）。
- 换行把关键词或数字切开时**宁可不加**（不出现半截强调）。
- **可编辑性（真机已验证）**：`<tspan>` 不带 `x`/`dy`，ppt-master 原生转档后是**同一段落的多个 DrawingML run**
  （各带自己的 `sz` / `b` / 颜色）—— 例如 `按区域建台账` 是 `sz=1500 b=1 #0D47A1`、紧跟的 `，逐台贴码` 是
  `sz=1200 #37474F`，两段在同一个 `<a:p>` 里；文字在 PowerPoint 里照旧可编辑，不会变成图片、也不会拆成两个文本框。

**降级规则**（版式撑不起就落到「要点清单」，**内容只搬不删**）见 §六。
**兜底清单的次要说明行**来自这一条自己的后半句——在第一个"两边都够长"的标点（`：，；、`，主句 ≥6 字、说明 ≥4 字）处断开，
断不出就只画主句那一行（垂直居中）。**内容不重复、不硬拆**。

## 五、七种布局

`layout` 取值只有这七个（旧 #141 的「要点」「图文说明」按 `PPT_LAYOUT_ALIASES` 映射到「要点清单」；
别的取值按兜底布局处理）：

| 布局 | 用什么字段 | 数量与限额 |
|---|---|---|
| `网格要点` | `blocks` | **恰好 4 块**（2×2，3 块也照画），块头 ≤14 字、小注 ≤24 字（可空）、每块 3–4 行、每行 ≤26 字 |
| `双栏对比` | `columns` | **恰好 2 组**，栏头 ≤14 字、小注 ≤24 字（可空）、每组 3–5 行、每行 ≤26 字 |
| `流程阶段` | `stages` | 3–5 个，阶段名 ≤14 字、说明 ≤24 字 |
| `分层架构` | `layers` | 3–4 层，层名 ≤14 字、每层 2–4 个组件、每个 ≤10 字 |
| `数据卡片` | `cards` | 3–4 张，`value` ≤8 字、`label` ≤14 字 |
| `表格` | `table` | ≤5 列（表头 ≥2 列）× ≤6 行，表头 ≤8 字、单元格 ≤20 字；**行与列都要写满** |
| `要点清单` | `bullets` | 3–6 行（渲染 5–6 行），每行 ≤26 字 |

页级字段（每页都要给）：`kicker` ≤8 字、`title` ≤20 字、`subtitle` ≤32 字、`highlight` ≤34 字、`chips` 0–5 个（每个 ≤10 字）、
**`icon` 1 个**（页图标，取自 `PPT_ICONS`）；每个 `blocks` / `columns` / `stages` / `layers` / `cards` 元素各带 1 个 `icon`；
`table.icons` 与表头列一一对应（列讲什么就给什么，几列给几个）——**清单外的名字由领域层回落 `presentation`**（#144）。

**`layout` 与字段必须成套**（#142 真跑教训，写进提示词当硬约束）：

- 声明 `表格` ⇒ **必须**同时给合规 `table`；声明 `流程阶段` ⇒ 必须给 3–5 个 `stages`（每个都要 `head` + `note`）；
  声明 `分层架构` ⇒ 必须给 3–4 层 `layers`；声明 `网格要点` / `双栏对比` ⇒ 必须给满 4 块 / 2 栏。
- **只写 `layout` 不给字段的页会被降级成兜底清单**，页面上就只剩两三条——所以提示词里写死了一句：
  **"给不出字段就换版式，拿不准就一律用 `网格要点` 写满 4 块"，宁可用网格要点写满，也不要交一页只有两三条的空页。**

## 六、确定性校验与兜底（`packages/domain/src/ppt-outline.ts`）

`parsePptOutline(text)` 是**唯一入口**，逐条判定（判定留在确定性层，模型只产内容）：

| 情形 | 处理 |
|---|---|
| 没有 JSON / 不是 JSON / 缺 `pages` / 一页可用都没有 | **明确失败值**：`outline: null` + `error`（调用方重试一次，仍失败 → `notice` + 不产文件） |
| 页数 > 10 | 截掉尾部页面，`dropped` 计数并提示 |
| 页数 < 5 | 先按「重试一次」再判（见 §八）；重试后仍不足则**保留**（无法凭空造页），记提示「少于 5 页下限」 |
| 页面不是对象 / 没有标题 / 内容为空 | 丢这一页（`dropped`），其余页照常 |
| 缺 `layout` / 旧布局名 / 取值不认识 | 旧名按别名映射（要点、图文说明 → 要点清单）；不认识按兜底布局并记提示 |
| 字段超字数、组数超上限 | **截断**（`trimmed` 计数），截断不许把一页删空 |
| `kicker` 缺失 | 用标题前 8 字兜底（每页必须有小节标签，记提示） |
| `highlight` 缺失 | 用 `subtitle`；副题也空 → 用 `title`（每页必须有结论带） |
| `subtitle` 缺失 | 回退旧字段 `takeaway`（#141 兼容） |
| `icon` 缺失 / 不在 `PPT_ICONS` 里 / 带库前缀 | `normalizePptIcon` 归一：剥掉 `lib/` 前缀，仍不认识就用 `PPT_DEFAULT_ICON`（`presentation`）；**不丢页、不报错**（#144） |
| `table.icons` 少于列数 | 缺的那几列兜底 `presentation`（一列一个，绝不越界）（#144） |
| `blocks` 缺失但有旧字段 `bullets` | 折成 1–2 块（每块 ≤4 行，块头用标题） |
| `网格要点` 不足 3 块 | **有几块画几块**；少于 3 块 → 降级「要点清单」（内容搬到 `bullets`） |
| `双栏对比` 不足两栏 / `流程阶段` 不足 3 个 / `分层架构` 不足 3 层 / `数据卡片` 不足 3 张 / `表格` 页没有合规表格 | 降级「要点清单」，本布局的内容摊平成一行行短句（**一条不丢**） |
| `kicker` / `title` / `subtitle` / `highlight` 命中禁用词 | 丢整页（页级问题只能丢页） |
| 块行 / 栏行 / 阶段 / 层 / 组件 / 卡片 / 标签 / 表格行命中禁用词 | 擦掉该条（`scrubbed` 计数），页保留 |
| 命中禁用词的**表头** | 该表作废 → 降级「要点清单」 |
| **某页有效短句太少（空页）** | 领域层把它数出来（`pageSentences`，见下），调用方按**本版式的判定线**（§八.2）**重试一次**；重试仍偏少则保留并进下一轮反馈，三轮都没改掉就照常导出 + notice 点名第几页（不阻断） |

**每页有效短句数**（`pptPageSentences(page)`，随 `parsePptOutline` 结果一起返回，与页同序同长）：

| 布局 | 怎么数（**不含**小节标签 / 标题 / 副题 / 结论带 / 页码 / 页脚这 6 条固定骨架文本） |
|---|---|
| 网格要点 / 双栏对比 | 每块（每栏）= `head` + `note` + 每行一条 |
| 流程阶段 | 每个阶段 = `head` + `note` |
| 分层架构 | 每层 = `head` + 每个组件 |
| 数据卡片 | 每张 = `value` + `label` |
| 表格 | 表头格 + 每个数据格 |
| 要点清单 | 每行一条 |

> 口径与渲染一致，任务是"这一页有没有话说"。**判定线在调用方**：`apps/server/src/ppt-export.ts` 用
> `min(12, pptLayoutSentenceMax(layout))`（#146；比质量门禁的 12 条更严，因为门禁把 6 条固定骨架也算进去了）——
> 网格要点/表格等容量大的版式按 12 条判，`流程阶段`/`数据卡片`/`要点清单` 这三个结构上给不满 12 条的版式
> 按各自上限判（10 / 8 / 6），否则它们永远不可能达标（§八.2）。真跑抓到的"一页只有 2 条"就是这样被拦下的。

**禁用词三类**（`PPT_BANNED_PATTERNS`，与《建设工作方案输出要求》§五、§六同口径）：

1. **占位**：待客户提供 / 待补齐 / 待现场勘查 / 待确认 / 暂缺 / 未提供 / TBD；
2. **决策建议**：建议先 / 建议采用 / 建议采购 / 推荐采用 / 推荐方案 / 值得投入 / 应当优先 / 不建议 / 可以决定；
3. **内部痕迹**：来源：/ 出处：/ 摘自：/ 参见：/ `表X-X` / `ingest-*` / 证据级 / 权威性 / 核实结论 / 信息完整度 / 信息缺口。

> **数字不许编造**由**提示词侧**硬约束（「只用报告正文里出现过的数字，金额/台数/比例一律不许新造」）：
> 检测"这个数字是不是新造的"要与正文逐句比对，误伤率高（如「八个环节」写成「8 个环节」），
> 故不进确定性层——与《建设工作方案输出要求》§8.1 的既有取舍一致。确定性层挡的是**禁词与形状**。

## 七、质量门禁（`packages/infra/src/ppt-quality.ts`，变更表 #142 立、#144 升、#145 升）

渲染完的 SVG 是**可以量的东西**。`checkPptDeck(svgs)` 返回问题清单（空数组 = 合格），判据全在确定性层。
**阈值集中在 `PPT_MIN_QUALITY`**（`note` 字段写死"本组阈值是用户定调的 PPT 最低要求：只许收紧，不许放宽"），
导出链路直接引用它——它是这份交付物的**最低要求**，不是"参考值"。

| 判据 | 阈值 | 问题码 |
|---|---|---|
| 每页形状数（`<rect|<text|<line|<path|<circle|<polygon>` 计数） | **≥ 22** | `页面太空` |
| 每页必须有小节标签胶囊（`<g id="kicker">` 且组里有非空文字） | 必须 | `缺小节标签` |
| 每页必须有结论带（`<g id="highlight">` 且组里有非空文字） | 必须 | `缺结论带` |
| 文本矩形不出 1280×720 的**8px 安全边** | 必须 | `文本越界` |
| 同一页任意两块文字不相交（两个方向重叠都 >4px 才算） | 必须 | `文本相交` |
| 页面上的文字条数（非空 `<text>` 计数，**同一行的多个 `<tspan>` 算一条**） | **≥ 12**（`PPT_LIMITS.minSentencesPerPage`） | `信息量不足` |
| 页面上的图标数（数 `data-icon` 占位；收尾后数 `<!-- icon:` 注释或图标包层 `*-icon`，**不数 `<path>`**） | **≥ 4**（`PPT_QUALITY.minIconsPerPage`） | `图标不足` |
| 页面不同颜色数（`#RRGGBB` 去重） | **≥ 6**（`PPT_QUALITY.minColorsPerPage`） | `颜色层次不足` |
| 页面强调处数（`<tspan>` 字内强调段 + **16px 以上**粗体字） | **≥ 3**（`PPT_QUALITY.minEmphasisPerPage`） | `重点不突出` |
| 字号：内容文字（除页脚 / 页码） | **≥ 16px**（`PPT_MIN_FONT`） | `字号过小` |
| 字号：页脚 / 页码（`<g id="footer">` / `<g id="page-no">` 里的文字） | **≥ 15px**（`minMetaFontSize`） | `字号过小` |
| 内容元素（`<g id="body">` 里的文字与图形）距画布四边 | **≥ 40px**（`minContentMargin`） | `超出安全边` |
| 同层级元素的 x / 宽 / 高落在版式网格上（块 550×216 在 `x=80/650`、`y=170/400`，栏 550×450，层 1120，清单/表格行 1120，卡片与阶段同宽等距） | 偏差 **≤ 2px**（`gridTolerance`） | `未对齐网格` |
| 内容区（`y=170..620`）底部空白 | **≤ 120px**（`maxBottomGap`） | `留白不均` |
| 任一行文字不以 `，。、；：！？）》」` 开头（中文行首禁则） | 必须 | `行首标点` |
| 换行段最后一行 ≥3 个字（以 `…` 收尾的压缩行豁免） | 必须 | `孤字行` |

- 文本矩形按显式基线估算：`上 = y − 0.86em`、`下 = y + 0.22em`，宽度用与渲染同一把尺 `estimateTextWidth`；
  **一个 `<text>` = 一个矩形**：同一行里的多个 `<tspan>` 合并计宽（不与自身判压字），垂直范围按段里最大的字号算（#144）；
- 为什么落在基础设施层：判据的输入是**渲染产物**（SVG 字符串），而依赖方向只允许「基础设施 → 契约」，
  领域层不能反向依赖基础设施；判据本身是纯函数、可单测；
- 单测里用它锁住"7 页示例大纲：每页 ≥22 形状、**≥4 图标、≥6 颜色、≥3 处强调**、0 越界、0 压字、kicker/highlight 齐"，
  也锁住**"兜底要点清单 5 条 ≥22 形状且 0 问题"**、**"真跑那种只剩 2 条的空页仍然会被抓（`信息量不足`）"**
  与九条判据各自的**正反例**（没图标 / 一层白 / 整页没有粗体与 tspan / 15px 正文 / 贴边 / 块宽差 8px /
  底部空 300px / 行首逗号 / 末行 2 个字，都要报）；
  真机验收时也可直接量 `svg_output/`（未收尾）或 `svg_final/`（收尾后）里的文件。

### 七.1 #145 六条版面判据怎么量

| 判据 | 量法（都在确定性层，纯函数） |
|---|---|
| `字号过小` | `svgTextRects` 逐个文字块看 `font-size`；**组路径**里含 `footer` / `page-no` 的按 15px 判，其余一律 16px |
| `超出安全边` | 只看 `<g id="body">` 里的内容元素（文字矩形 + `rect/line/circle/polygon` 的框）；**骨架不参与**——结论带底边 684 距画布底只有 36px，那是版式本身的选择 |
| `未对齐网格` | 取各组第一个 `<rect>`：`block-N` / `col-N` / `layer-N` / `item-N` / `row-N` / `table` 按上表基准；卡片与阶段还要**同宽 + 等距 + 起点在 x=80**；偏差 ≤2px 算对齐 |
| `留白不均` | 内容区所有元素的**最下沿**与 `y=620` 的差 >120px 就报（"内容挤在上半页"），文案里给出实际留白像素 |
| `行首标点` | 每个文字块的文本 `trim()` 后首字符是否落在禁则集合里（渲染层的断行已经保证不出现，这里兜我们的 bug） |
| `孤字行` | "同一个换行段"= 同一组（`…-text` / `card-1-value`）+ 同字号 + 同 x + 行距落在 1.1–2.2 倍字号之间；末行 <3 字且不以 `…` 收尾就报 |

### 七.2 生成后版面检查：检查 → 反馈 → 重跑（最多三轮）（#145 立、#146 升）

**渲染完立刻跑一遍，不许跳过**（`apps/server/src/ppt-export.ts`）。检查两路一起做，产出一份**问题清单**：

| 检查 | 判什么 | 落点 |
|---|---|---|
| 版面 | 密度 / 骨架 / 越界 / 压字 / 信息量 / 图标 / 颜色 / 强调 / 字号 / 安全边 / 网格 / 留白 / 行首标点 / 孤字行（§七.1） | `checkPptDeck`（阈值 `PPT_MIN_QUALITY`） |
| 大纲 | 标题是不是观点 / 记忆点 / 信息量 / 数字可溯源 / 两页重复 / 叙事顺序 / 自包含 / 图标与版式（§八.1） | `checkPptOutlineQuality`（阈值 `PPT_OUTLINE_QUALITY`） |

问题按性质分两类（`PPT_CONTENT_ISSUES` / `PPT_RENDER_ISSUES`，`isPptContentIssue` / `isPptRenderIssue`）：

| 分类 | 问题码 | 处理 |
|---|---|---|
| **内容类**（模型没写够） | `信息量不足`、`图标不足`、`重点不突出` | 与大纲类问题一起进**下一轮的反馈**（生成提示 + 优化提示都带上，点名到页），下一轮重读正文重写 |
| **渲染类**（确定性缺陷） | `页面太空`、`缺小节标签`、`缺结论带`、`文本越界`、`文本相交`、`颜色层次不足`、`字号过小`、`超出安全边`、`未对齐网格`、`留白不均`、`行首标点`、`孤字行` | **不指望模型改**（重试一百次也没用）：渲染层（`ppt-svg.ts`）已经修到达标，这里再判出来就是我们的 bug → `console.warn` 一行点名；它同样进问题清单，所以通常会走到下面"三轮没全过"那条路 |

**问题清单为空 → 立刻导出**（进度报 `PPT：版面检查通过（N 页）`）。
**不为空 → 不改口径、不报错，而是把清单原样喂回下一轮**（最多三轮，见 §八.5）；
三轮都没拿到空清单时，**取问题最少的那一轮照常导出**，notice 如实点名：

```
已生成，但仍有 2 处未达标：第 5 页信息量不足：只有 10 条有效短句，少于 12 条；第 2 页未对齐网格：偏差 7px
（大纲最低要求：标题是一句判断（不是「项目概述/项目背景/项目概况」这类章节名）、每页 ≥12 条有效短句、
数字只能来自报告正文、不许两页说同一件事、叙事按 问题 → 方案 → 价值；最低要求：内容字号 ≥16px、
内容距画布边 ≥40px、内容区底部留白 ≤120px；已按问题最少的一轮（第 1 轮）导出）
```

- **#146 作废 #145 的"拒绝写出"**：用户原话「**不是不满足标准就报错或者什么的**」——不达标是**如实告知**，
  不是阻断。三轮跑完**文件一定产出**（"问题最少的一轮"若不在最后一轮，会按它重新渲染一次再转档），
  notice 里点名第几页、什么问题、卡在哪几条线上；
- 两处"最低要求"都是**现取的**：大纲那几个词/阈值取自 `PPT_OUTLINE_QUALITY`、版面三个数取自 `PPT_MIN_QUALITY`
  （改阈值就会改文案，改不动才怪）；
- 进度三条：`PPT：正在做版面检查…` → 过了报 `PPT：版面检查通过（N 页）`；三轮都没过报
  `PPT：三轮仍未全达标，按问题最少的一轮（第 K 轮）导出…`；
- 检查仍在**图标收尾与转档之前**，但**不再**因此拒绝转档：问题只决定"要不要再来一轮"，不决定"出不出文件"；
- **旧文件保护不变**：不管走哪条路，落盘都走 `safeWriteFileBytes` 的先读后写（不覆盖用户改过的文件，
  内容没变记 `unchanged`）；
- 单测锁死：第一轮通过 → 恰好 1 次生成 + 1 次优化；第一轮不通过、第二轮通过 → 第 2 轮的提示词里带着第 1 轮的问题、
  且正文被**重读**；三轮都不通过 → 照常导出 + notice 点名 + 导出的确实是**问题最少的那一轮**；
  渲染类问题 → 一次都不少跑，但只 `console.warn`，照样导出。

## 八、大纲质量要求（变更表 #146 立：可执行的大纲规范）

**为什么单独立一章**：这一页页的内容是模型写的，但"写得好不好"不能靠感觉。所以这里不是几条注意事项，
而是**八条可判的要求**——每条都有判据、有落点、有失败时的处理，判据全部落在确定性层
（`packages/domain/src/ppt-outline.ts` 的 `checkPptOutlineQuality`，纯函数、可单测、可审计；模型只负责写内容）。

### 八.1 八条硬要求（逐条可判）

| # | 要求 | 判据（确定性层怎么判） | 问题码 |
|---|---|---|---|
| ① | **标题必须是观点，不是章节名** | 标题 ≤20 字；命中弱词表（`weakTitleWords`：项目概述 / 项目背景 / 现状 / 小结 / 方案说明 / 建设内容…）或**≤8 字且不含判断词**（`judgmentWords`：把 / 要 / 不再 / 必须 / 让 / 从…到…）→ 报 | `非观点型标题`、`标题超长` |
| ② | **每页都要有记忆点** | 每页必须有 `highlight`（底部结论带）且 ≤34 字；缺失或超长 → 报 | `缺记忆点` |
| ③ | **每页信息量到下限** | 每页有效短句数 ≥ **本版式判定线**（§八.2，`min(12, 版式结构上限)`）→ 否则报 | `信息量不足` |
| ④ | **数字只能来自报告正文** | 页内每个阿拉伯数字都要能在正文里**原样找到**（全角→半角、去空格后比对）；中文数字只在带量词时兜底（「八个环节」可兜「8 个环节」，「统一」不兜「1」）；找不到就报 | `数字不在正文` |
| ⑤ | **不许两页说同一件事** | 归一（去标点/空格）后 ≥6 字的句子，出现在 ≥2 页 → 报；每页最多报 3 处；≤4 字的块头不查（网格要点本来就有通用块头） | `两页重复` |
| ⑥ | **顺序：问题 → 方案 → 价值** | 按 `kicker` / 标题 / 副题 / 结论带里的用词，把每页归到「现状与问题 / 方案与建设 / 价值与收益」三组之一，页码必须**非递减**；归不进任何组的不算错 | `叙事顺序错` |
| ⑦ | **自包含** | 页内不许出现指代（见上文 / 如前所述 / 详见第 N 页 / 下文）与元话（本页 / 这一页 / 上面几页）——每页都要能被单独读 | `不自包含` |
| ⑧ | **图标与版式成套** | `icon` / 各元素 `icon` / `table.icons` 必须在 47 个白名单里（`PPT_ICONS`）；`layout` 必须与字段成套（`表格`⇒`table`、`流程阶段`⇒3–5 个 `stages`、`分层架构`⇒3–4 层、`网格要点`⇒4 块、`双栏对比`⇒2 栏、`数据卡片`⇒3–4 张） | `图标不合规`、`版式与字段不成套` |

判据的**取舍原则**（与《建设工作方案输出要求》§8.1 同一条）：宁可少报也不误伤——弱词表与判断词表都取宽，
数字比对做全角/空格归一，重复只查 ≥6 字的整句；**确定性层只判"能不能一眼看出不合格"，不替模型改写**。
反过来，判出来的每一条都会**点名到页 + 说清为什么**（如「第 5 页两页重复：第 1 页与第 5 页说了同一件事：「…」」），
下一轮模型能照着改。

### 八.2 每个版式的判定线（结构上给不满 12 条的按上限判）

有效短句数的口径同 §六（块 = 块头 + 小注 + 每行一条；阶段 = 阶段名 + 说明；卡片 = 值 + 说明…）。
`pptLayoutSentenceMax(layout)` 是**这个版式结构上的最大短句数**，判定线取 `min(12, 上限)`：

| 版式 | 结构上限（按限额算） | 判定线 | 为什么 |
|---|---|---|---|
| `网格要点` | 4 块 ×（1 头 + 1 注 + 4 行）= 24 | **12** | 主力版式，占一半以上 |
| `双栏对比` | 2 栏 ×（1 + 1 + 5）= 14 | **12** | 大版式，够得着 12 |
| `分层架构` | 4 层 ×（1 + 4 组件）= 20 | **12** | 同上 |
| `表格` | 5 列 × 6 行 + 5 表头 = 35 | **12** | 同上 |
| `流程阶段` | 5 阶段 ×（1 + 1）= 10 | **10** | 最多 5 阶段，给不满 12 |
| `数据卡片` | 4 张 ×（值 + 说明）= 8 | **8** | 最多 4 张 |
| `要点清单` | 6 行 × 1 = 6 | **6** | 兜底版式 |

> 判定线只用来判"这一页有没有话说"：写满结构上限的版式就不会被判 `信息量不足`。要让每一页都到 12 条，
> 就选容量大的三种（网格要点 / 双栏对比 / 分层架构 / 表格）；提示词里也写死了这条对应关系（§八.3）。

### 八.3 生成提示词里怎么组织（`apps/server/src/ppt-prompt.ts`）

system 里按**"要求 → 常见错误"**的顺序给模型（不是散着写几条）：

1. **八条要求逐条成节**（`PPT_OUTLINE_QUALITY_RULES`，标题就是 §八.1 那八条）；
2. **常见错误 ❌→✅ 清单**：标题 ❌「项目概述」「背景」「现状」「小结」「设备清单」 → ✅「四条硬规则管住现场」；
   一页只有 3 条 ❌ → 4 块 × 3–4 行 ✅；写「47 台」正文里没有 ❌ → 只能用正文里的数字 ✅；
   两页都写「统一口径」❌ → 每页只讲自己那一面 ✅；把「价值与收益」放在第 2 页 ❌ → 按 问题 → 方案 → 价值 ✅；
   写「详见第 3 页」❌ → 每页自包含 ✅；声明「表格」不给 `table` ❌ → 字段成套 ✅；
3. **词表与阈值从契约现取**（弱词表、判断词、记忆点字数、每页条数、自包含禁语都写进提示词）——
   改契约就改提示词，两处不会走偏；
4. **四页完整示例 JSON**（网格要点 / 双栏对比 / 流程阶段 / 表格，都是**填满**的），字段名与限额与契约逐字一致；
5. **图标白名单原样贴**（47 个名字，一个字母都不许改）+ 写死"选不出就用 `presentation`、不许自创名字"，
   并给按意思挑的对义提示（台账→`file-text`、网络→`network`、风险→`alert-triangle`…）；
6. **版式与字段必须成套**一节（§五）+ "拿不准就用网格要点写满 4 块，不要交一页只有两三条的空页"；
7. **上一轮的问题**（`## 上一轮的问题（这一轮必须点对点改掉，别再犯）`）——有反馈就贴，没有就不加这一节；
8. 输出**只有 JSON**：不要解释、不要 Markdown 围栏、不要前后缀（直接 `JSON.parse`）。

### 八.4 优化大纲：每轮都跑的第二次模型调用（#146 新增）

生成完不是直接渲染，而是**先把大纲交给模型自己过一遍**（`buildPptOutlineReviewPrompt`）：

- **输出只有优化后的完整 JSON**（schema 与生成时逐字相同）；
- **不许删内容**：页数不得减少、字段不得清空——只许改写的更准、更满、更清楚；
- **点对点解决**问题清单里的每一条（清单为空时也要整体按 §八.1 过一遍：这一步永远跑，第一轮也跑）；
- system 里带**全套质量要求 + schema 示例 + 图标白名单**，所以优化不会把稿子改跑偏；
- user 里带 `## PPT：只输出优化后的完整 JSON（大纲评审）` 这段标记（可用它定位提示词）、原大纲 JSON、
  问题清单、第几轮；结尾一句"只输出 JSON。"。

### 八.5 三轮闭环：重读正文 → 重写 → 优化 → 渲染 → 检查（最多 `PPT_OUTLINE_ROUNDS = 3` 轮）

```
第 K 轮（K = 1..3）
  ├─ 重读正文（getReport：每一轮都从文件重新提取，界面所见 = 导出所得）
  ├─ 生成大纲（buildPptOutlinePrompt，带上第 K-1 轮的完整问题清单）
  │    └─ 轮内重试一次（4 种情形，见下）→ 择优采纳
  ├─ 优化大纲（buildPptOutlineReviewPrompt，同一份问题清单 + 原大纲）
  ├─ 解析 + 确定性校验（parsePptOutline：截断 / 降级 / 禁词 / 页数 clamp）
  ├─ 逐页渲染 SVG
  └─ 检查：checkPptDeck（版面）+ checkPptOutlineQuality（大纲）→ 问题清单
        空 → 「PPT：版面检查通过（N 页）」→ 收尾 → 转档 → 落盘（结束）
        不空 → console.warn 一行 → 进下一轮
三轮都不空 → 取问题最少的那一轮（先比问题数，再比页数）→ 必要时按它重渲染 → 收尾 → 转档 → 落盘
             notice：「已生成，但仍有 N 处未达标：第X页…」+ 两条"最低要求"（§七.2）
```

**轮内重试一次**（四种情形，与 #145 口径一致，各只重试一次）：① 解析不出来；② 页数少于 5 页下限；
③ **某页有效短句低于本版式判定线**（§八.2）；④ 生成调用本身报错。
重试提示把卡在哪**点名到页**（如「第 5 页只有 2 条（每页请写到 12 条以上），重试一次…」）并要求整页重写；
**择优采纳**：首次本来就不可用 → 用重试那份；首次只是偏少 → 只取更好的那份（先比偏少的页数、再比页数），
重试吐垃圾时保留首次（继续往下走）。

**反馈怎么流动**：第 K 轮的完整问题清单同时进第 K+1 轮的**生成提示**（system 里的「上一轮的问题」一节）
与**优化提示**（user 里的问题清单）——所以模型既知道"上一稿哪里不合格"，也知道"这一稿要重点改哪里"。

**为什么是三轮**：一轮改不完的问题（比如渲染类缺陷、模型反复犯同一个错），第三轮再加也不会更好；
三轮的上限把"最多 9 次模型调用"钉死（每轮最多 生成 + 重试 + 优化），不至于让一次点击拖到十分钟。
进度文案：`PPT：正在从正文提取大纲（第 K 轮）…` → （重试）`PPT：…，重试一次…` → `PPT：正在优化大纲…`
→ `PPT：大纲 N 页，正在渲染第 K 页…`（每页一条）→ `PPT：正在做版面检查…` → 通过报
`PPT：版面检查通过（N 页）`，没通过报 `PPT：三轮仍未全达标，按问题最少的一轮（第 K 轮）导出…`。

### 八.6 调用与输出纪律

- 生成与优化都走 **DSH 客户端**（`createSession` + `prompt`，与交付物正文生成同一条链路），
  流式期间照 `streamPrompt` 的心跳文案报"仍在写"；**同一个会话**内完成"生成 → 优化"，不另起会话；
- 重试与下一轮都用**同一份正文**的新鲜副本（每轮重读），不缓存上一轮读到的 markdown；
- 提示词里写死的口径：**5–10 页（目标 7）** / 无封面目录尾页 / 问题 → 方案 → 价值 /
  **每页 ≥12 条有效短句（≈4 块 × 3–4 行）、空页一律不合格** / 版式与字段成套（§五）/
  内容从正文提炼、数字不编造 / 七种布局各自怎么用（网格要点占一半以上，同一布局不连排两页）/
  各字段限额 / 禁占位与决策建议 / 不写表号来源页码 / 说人话。

## 九、导出链路

```
PPT_MASTER_DIR（默认 ~/.dsh/skills/ppt-master）
        │  ① 技能缺失 → notice「PPT 导出组件未就绪：找不到 ppt-master 技能」，不产文件
```

- **转档参数逐字固定**（`-o … --no-compat -f ppt169`）：**不加 `-s final`**——原生模式读 `svg_output/`，
  并在内存里把 `<use data-icon>` 展开成真图标（`svg_to_pptx/use_expander.py` → `svg_finalize/embed_icons.py`），
  所以图标进不进 pptx 不依赖上一步；第 ⑤ 步是**保险丝**（给读 `svg_final/` 的老技能/回退路径留一份收尾好的产物），
  失败绝不影响导出（真机实测：finalize 输出 `svg_final/`，转档仍读 `svg_output/`，7 页共展开 40 个图标）；
- `--no-compat` **必须带**：本机没装 cairosvg，Office 兼容模式会失败；原生模式输出的形状在 PowerPoint 里可编辑；
- 技能路径可配：优先环境变量 `PPT_MASTER_DIR`，默认 `~/.dsh/skills/ppt-master`；**只读使用，不修改技能目录**；
- **`unchanged` 的实情**：转档产物（python-pptx）内含生成时间戳，同一份内容两次导出的字节通常不同 →
  实际几乎总是重写并报 `files`；`unchanged` 分支是"先读后写"的机制保障（内容真的一样时不碰文件），
  不要把它当成"不会重复写盘"的承诺；
- 用户手改过目标 pptx 时，走同一套保护：**不覆盖**，另存「(应用版 时间)」并在 `notice` 里说明。

## 十、过程可见（1–3 分钟不能干等）

PPT 导出比 Word 慢（多一次模型调用 + 逐页渲染 + 转档），进度走**现有 SSE 通道**，与结果分成两条线：

1. 前端先生成 token，订阅 `GET …/deliverables/export-pptx/events?run=<token>`；
2. 再 `POST …/deliverables/export-pptx`（body 带同一个 `run`）；
3. 服务端一路推进度：`PPT：正在从正文提取大纲（第 K 轮）…` → （轮内重试时 `PPT：第 N 页<问题>，重试一次…`）
   → `PPT：正在优化大纲…` → `PPT：大纲 N 页，正在渲染第 K 页…`（每页一条，不刷屏）
   → `PPT：正在做版面检查…` → 过了报 `PPT：版面检查通过（N 页）`；三轮都没过报
   `PPT：三轮仍未全达标，按问题最少的一轮（第 K 轮）导出…`
   → `PPT：正在嵌入图标…` → `PPT：正在转成 PPTX…` → `PPT：已导出 <文件名>`；
   模型长思考期间由 `streamPrompt` 的心跳补"仍在撰写"；
4. 前端把阶段文案**顶在按钮上**（不是只有「导出中…」）；失败或 `notice` 时原因原样提示、按钮恢复可点、
   **已有的产物不清空**（可以反复点）。

两边谁先到都行：通道按 token 幂等创建，订阅先到就先把 run 建起来，导出先到就由中枢重放已缓冲的进度；
没人取用的通道 15 分钟后自动收尾。

## 十一、已知边界

- 不做封面 / 目录 / 尾页 / 分节页（用户明确不要）；不做图片、图表、动画（零图片：示意图与卡片全部由形状确定性拼出来）；
- 不做"演讲备注"（`--no-notes` 之外的备注体系不接）；
- 页数不足 5 页时不补页（无法凭空造页），只在 `notice` 里说明；
- 三轮闭环的上限是**固定 3 轮**（`PPT_OUTLINE_ROUNDS`）：不加轮数不是因为改不动，而是因为"每轮最多 3 次模型调用"
  是给用户的等待时间上的承诺（一次点击 1–3 分钟），第四轮以后收益极小而代价线性增长；
- **模型仍交了空页 / 标题是章节名 / 数字对不上正文时**（#146 改口径）：不报错、不拒绝写出——判据把问题点名到页，
  进下一轮反馈重写；三轮都没改掉就**照常导出**并在 notice 里如实说明（用户定调：「不是不满足标准就报错或者什么的」）。
  确定性层不会替模型编内容，所以"改不掉"是如实告知，不是阻断；
- **最低要求冻结**：字号 ≥16、六条版面判据、生成后必做的版面检查都是**下限**（`PPT_MIN_QUALITY`），
  **#146 起大纲八条判据同样是下限**（`PPT_OUTLINE_QUALITY`：观点型标题 / 记忆点 / 信息量 / 数字可溯源 /
  不重复 / 叙事顺序 / 自包含 / 图标与版式），改动它们等于改交付标准，必须走变更表；
- 标签/组件胶囊排不下时**从右往左少画一个**（内容不丢，只是不上这一页的那一行）——视觉优先，不压字；
- 真跑依赖本机 ppt-master 技能与 `python3`；单测一律用假导出器（fixture，**含假的 finalize_svg.py**），不依赖本机；
- **图标库版本依赖**：白名单里的 47 个名字都在 `tabler-outline/` 下逐个核对过；换机器/换技能版本时若某个名字不存在，
  ppt-master 会把那个占位**原样留在 SVG 里**（不报错、不崩），门禁的图标计数会随之少一个——提示词写死清单与兜底就是为了把这种情况挡在前面（#144）。
