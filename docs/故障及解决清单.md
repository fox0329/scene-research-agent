## #25 按表并发后整步报「完成」，但最后几张表的数据没落库

**现象**：第 2 步重算返回 `done`（无任何告警），中栏却少了「表2-3 分层架构表」「表2-4 要素间关系表」的内容；
原始输出留证里也找不到这两张表的文件。实测一次只落了 5 张表 60 行。

**原因**：调度循环的退出条件写成了「**全部开始**」——`while (started.size < coveredCodes.length)`。
并发下"开始"和"结束"不再同步：最后起始的依赖表（表2-3/表2-4 要等表2-2）刚被起跑，
循环就判定收工返回，两张表还在飞的任务被丢下。更糟的是它们连 `results` 都没有条目，
于是"失败表"统计也漏了它们——**报成功、静默丢数据**。

**解决**：
1. 退出条件改为「全部**结束**」（`settledCount`），另加"没有在跑的任务就收工"的兜底，绝不空转；
2. 任务用 `.catch()` 兜住异常并写入 `results`（失败的依赖不能让下游干等，也不能从统计里消失）；
3. 单表失败当场用 `⚠️` 进度事件说出来（只在收尾汇总里提一句，用户看不到是哪张表卡住的）；
4. 补回归用例「最后才起始的依赖表也必须落库」——故意让依赖表最慢，断言它的行必须落库。

**同一处踩到的第二个坑**：「就绪」原来只判依赖**已开始**（`started.has(dep)`）。
依赖还在跑时下游就被放行，注入的上游上下文是空的，口径照样对不上（表2-4 拿不到表2-2 的要素名）。
改为只判依赖**已完成**（`finished.has(dep)`），并把死锁兜底收紧为"没有任何在跑的任务且一个都起不来"
——否则正常等待也会被兜底误放行。

**教训**：并发的调度条件里，「已开始」和「已完成」是两个必须分开的事实；退出条件审查一遍
"我等的到底是开始还是结束"。
## #26 「阶段 N 补填」的列永远填不上（跨阶段补填是死设计）

- **现象**：表2-5 物理与合规约束的「实现路径 / 责任人」在界面上一直空着（线上 13 行全空）；表3-8 的「排序 / 多源验证 / 对应预算科目」同样全空。用户问「为什么没填」。
- **原因**：契约里这几列标了列级 `filledInStages`（表2-5 标 `[4]`、表3-8 标 `[3]`），写入时 `filterRowByStage` 会把「不属于本阶段」的列**主动剥掉**；但后续阶段不会回头更新上游表（阶段 4 只跑表5-1/5-3/5-4/5-5，阶段 3 只跑表4-1..4-5）——全仓没有任何回填逻辑（`crossStageTables()` 只被一个单测引用）。于是「以后再填」变成「永远不填」，界面上是一列永远空着的表头，用户只会以为是模型偷懒。
- **解决**：① 表2-5 删掉「实现路径 / 责任人 / 状态」（责任人本就有家：表5-3 实施计划的「负责人」）；② 表3-8 三列改为阶段 2 自己填；③ **整个跨阶段补填机制删除**（`TableDef/TableColumn.filledInStages`、`filterRowByStage`、`crossStageTables`、提示词的「跨阶段填写」标注、文档徽标），防止再次出现同类死列。
- **教训**：跨阶段补填只有在「后面那一步真的会更新上游表」时才成立；本产品的生成单位是**本步的表集**，列必须落在生成本表的那个阶段，否则就是死列。

## #27 枚举列大量非法取值：提示词只给了枚举名，没给取值

- **现象**：真实数据里 61 处枚举列取值落在注册表枚举之外——表3-8「痛到什么程度」写成 high/mid/low，表1-3「门槛类型」写成「资质门槛/认证门槛/资金门槛」，「行业通行处置」写成整句解释，表1-2「来源权威性」写成「中」。行校验会报「枚举非法」，但按设计不阻断入库，所以用户直接看到脏值。
- **原因**：`stage-prompts.ts` 的 `renderColumn()` 只输出 `枚举 ${c.enum}`——**枚举名**（如 `level_hml`），从不输出合法取值；输出契约的字段 description 也一样。模型只能猜，猜的是它训练里见过的英文/近义词。
- **解决**：两处都改成带取值：`枚举 level_hml，只能取：高 / 中 / 低`（取值由 `enumValues()` 从注册表取，不手写）。副本复跑同一阶段：非法枚举值 0 处。
- **教训**：契约里的枚举只有**同时出现在提示词里**才对模型有效；只给名字等于没约束。
