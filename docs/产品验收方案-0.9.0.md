# 场景通 产品测试验收方案（v0.9.0）

> 目的：基于 **2026-10-23 当前代码与安装包**，用一份可复跑的用例矩阵验收「能不能交付」。
> 原则：能用自动化判定的不靠肉眼；必须人看的，写清步骤与预期；每项留证据（命令输出/截图/接口响应）。
> 执行人：AI（自动化 + 接口 + UI 冒烟）；产品负责人做最终人工确认。

## 一、验收对象与范围

| 项 | 内容 |
|---|---|
| 版本 | 0.9.0（根 `package.json` 与 `apps/desktop/package.json` 一致） |
| 运行形态 | Electron 桌面应用 + 本机 Fastify 服务（随机端口，仅 127.0.0.1） |
| 核心范围 | 安装启动、品牌与导航、场景项目生命周期、6 步业务流程、信息表编辑、对话式场景定义、产物/交付物对话、资料库与入库、设置与模型、实时刷新、异常与数据安全、打包与升级 |
| 不在本轮 | Windows 真机（需 Windows 机器，列为本轮豁免）、签名/公证、外网检索通道可用性 |
| 数据 | 自动化用隔离库；安装包验收用真实库只读 + 一个临时项目 |

## 七、已知限制（本轮）

- Windows x64 真机未执行（需 Windows 机器）。
- macOS 安装包未签名/未公证，首次需右键打开。
- Windows 安装包必须放在「下载/桌面」等普通目录运行；DeepSeek Harness/公司管控工作区会给 exe 打低完整性标签，表现为双击无反应（故障 #104）。
- 长任务依赖模型端点；端点超时/限流会表现为可重试错误，不是数据丢失。
- 设置页「数据管理」如仍为占位按钮，按 H5 记 ❌ 并列入发布阻断项。
