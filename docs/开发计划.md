# 场景通 — 开发计划

> **状态**：v1.0（2026-09-22，依据技术方案 v0.3 §十五里程碑展开）
>
> **用法**：任务编号 `M<里程碑>-T<序号>`；状态三档（未开始 / 进行中 / ✅ 完成）；每个里程碑收口跑对应 `verify` 命令，全绿才算达成（技术方案 §十二验收自动化）。计划本身变更走 `docs/项目变更表.md`。
>
> **并行约定**（AGENTS.md 守则）：一任务一 worktree 一分支（`feat/<任务号>-<短名>`）；运行实例端口 4082+、DSH 端口 3082+；`DB_PATH` 指向 worktree 副本。任务表"依赖"列标明先后，无依赖的可并行。

## M6 · 业务流程逐页推进（增补里程碑，2026-09-25 用户拍板立项）

**背景**：M5 把 8 个阶段**并列成 tab**，等于把整套方法论摊开给用户看——一进来面对 8 个空表格，
与"用方法论帮用户一步步获得有价值、全面的信息"的产品定位直接冲突。改为**流程驱动**：
方法论藏在流程里，用户只回答"现在这一步"。

| 任务 | 内容 | 依赖 | 状态 |
|---|---|---|---|
| T6.1 | 契约：流程定义 `flow.ts`（9 步 + 本步表集，表集由注册表派生）+ 推进状态机（锁步/四态/就绪透传） | M5 | ✅ |
| T6.2 | 存储与服务端：`scenario_step` 表 + `scenario.flow_unlocked_all` + `flow-service`（就绪判定/完成/回退/解锁全部）+ 4 个流程端点 | T6.1 | ✅ |
| T6.3 | 步骤级分析：`advance?step=N` 按本步表集限定模型输出（阶段 1 第 3 步不再重复产出场景锚） | T6.2 | ✅ |
| T6.4 | 资料模型：产品资料库作全局基础设施（**默认合并主库**）+ 场景自有资料存储隔离 + 每行来源可区分 + 同型号本场景优先 | T6.2 | ✅ |
