# 资料入库标准（v1，2026-10-21）

> 回答两个问题：**入库有没有标准**、**怎么保证材料有效与客观**。
> 原则：能确定性判定的，全部由代码判定并留痕；判不了的，明确说「未保证」，不靠模型拍胸脯。

## 一、入库硬标准（不满足就不入库）

| 关卡 | 规则 | 判定方式 | 不满足的后果 |
|---|---|---|---|
| 格式 | 仅 `.pdf` / `.docx` / `.xlsx` / `.pptx` | 扩展名白名单 | 拒绝并说明支持格式 |
| 大小 | 单文件 ≤ 300 MB | 流式计数，超限即断 | 413 + 临时文件清理 |
| 可读文本 | 解析后正文非空 | 解析器返回 | 0 行文件单独点名，不静默吞掉 |
| 来源定位 | 每行 `source` 必须 `文件名:页码/章节`，页码为 `12`、`12-14`、`8.2`、`A.1` 之一 | 正则，确定性 | 该行不入库，回执给出原因；**「未知」不再放行** |
| 必填列 | 按表定义 required 列校验 | 契约定义 + 空值判断 | 该行不入库，回执照抄缺哪一列 |
| 硬结论 | 「不做」必须有可定位出处 + 非空依据 | `library-gate` | 不入库（宁可少一行） |
| 型号关联 | 规格必须挂到 M1 已有型号；报价型号必须在 M1 | 库内反查 | 不入库 |

## 二、入库质量分级（入库，但标清可信度）

| 规则 | 结果 |
|---|---|
| 权威级按**材料类目**判：法规标准/政府文件 T1；厂商官方/年报/行业报告 T2；媒体 T3；自媒体/口述/来源不明 T4 | 与「谁上传的」无关，不由模型自评 |
| 证据等级：T1–T3 → B；**T4 → C** | 自媒体材料不会被当成硬证据 |
| 绝对化措辞（100%、唯一、最强、完全、零风险、保证、必然、彻底解决、全部覆盖）命中 | 证据降为 C，写入 flagged 清单，行保留 |
| 来源抽查（G-R3）：每次入库抽 3 条回原文核对 | 结果进完整度报告；抽查不通过的文件，行证据降 C |
| 时效：文件名/出处含 4 位年份且早于当前 3 年 | 回执标「较早」，不阻断，但不当「最新」用 |
| 重复与冲突：同键同值跳过；**同键不同值不覆盖**，进冲突清单 | 冲突可见，由人决定采信哪份 |

## 三、入库回执（每次上传都给出）

- 逐文件行数 + 0 行文件点名；
- 证据分布（A/B/C/D 各多少）；
- 被挡行（哪张表、哪一行、为什么）；
- 冲突条数与两侧取值；
- 夸大措辞命中清单。

## 四、明确不保证的部分

1. **材料内容本身是否真实**：系统只能保证「这句话确实来自这份文件的这一页」，不能保证这份文件说的是事实。
2. **客观性**：系统能标注立场来源（厂商自述 vs 第三方标准）并降级，但不能替代交叉核验。
3. **最新**：只能按可见日期提醒「较早」，无法自动判定是否已有更新版本。
4. **扫描件/图片型 PDF**：识别质量决定可用性，识别失败按 0 行点名。

## 五、下一步（未实现，需单独立项）

- 入库后对关键事实（型号、价格、认证、门槛）做**联网交叉核验**，两源一致才升 A，冲突进「待核实」；
- 材料版本管理：同一文件新版本入库时，标出与旧版差异；
- 人工复核队列：C 级与被挡行集中在一个待办列表，而不是散落在回执里。
