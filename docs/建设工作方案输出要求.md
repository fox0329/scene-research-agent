## 二、总体口径

1. **读者**：客户的业务负责人与项目决策人。他们没看过我们的调研表，读到的必须是一份能独立成立的**建设工程方案**；立项、上会、报预算、迎监管都靠它。
2. **口吻**：给客户写建设方案的方案撰写人。全篇一条主线，**七问七答**——
   - **为什么建**（第 1 章）：现场今天怎么转、卡在哪、监管要求什么、不建会怎样；
   - **建成什么样**（第 2 章）：一句总体目标 + 2–4 条分项目标，每条一句结论式断言；
   - **建什么**（第 3 章）：分层架构长什么样、核心功能有哪几项、每项怎么运作、状态怎么研判分级；
   - **怎么建**（第 4 章）：数据从哪来（人工 / 物联 / 对接三类）、要新增哪些设备、花多少钱（试点与推广两阶段）；
   - **谁在什么时候做什么**（第 5 章）：一张计划表；
   - **怎么保障**（第 6 章）：组织、制度、资金、人才四条，每节一段；
   - **和监管怎么协同**（第 7 章）：1–2 段展望，不写承诺。
3. **不给决策建议**：不写"建议先做试点""推荐采用""值得投入""应当优先""不建议上""建议采购"。方案是**已经定了怎么建**的陈述，不是选项比较。
4. **不含内部信息**：不出现内部表号（表X-X）；不出现来源标注（文件名、页码、URL、"来源：/出处：/摘自：/参见："）；不出现证据等级、权威性、核实结论、信息完整度、待补齐/信息缺口；不出现 `ingest-*`；不出现竞品身份与竞争位势判断；不出现我方利润池与费用率测算。**注意区分**：第 4 章「数据采集」里的"来源"指**采集来源**（现场填报、设备远传、系统对接），这是方案内容，必须写；被禁的是**引用出处**（文件页码、材料 id）。
5. **篇幅**（表格不计入正文；两份参照件实测见 §六）：
   - 正文 **约 4,200–5,200 字**（生成目标）；两份参照件全文（含表格文字）实测 5,057 字与 5,445 字，本方案全文约 **5,000–6,300 字**；
   - 逐章字数基准（参照件实测最大值为下限抬高点）：背景 400–700 / 目标 400–800 / 内容 2,000–2,900 / 路径 500–1,000 / 安排 0（表格承载）/ 保障 400–600 / 展望 150–250 字；
   - 第 3 章「建设内容」是**天然的大章**（两份参照件分别占全文正文的 57% 与 49%），不要为了均摊篇幅把它压扁。
6. **表格与正文分工**：表格承载结构（分层、总览、清单、金额、计划、分级），正文给判断与代价。**同一事实只说一次**——能在表里说的，正文不再讲一遍；正文把表里的行逐条复述就是流水账。
7. **规则铁律**：
   - 只用调研得到的信息，不改数字、不引入材料外信息；
   - **客户没给的数与钱不许编**（见 §五 第 3 条）；
   - 不给决策建议、不含内部信息（见 3、4）；
   - **不写整段的自我说明与免责**（「本方案只陈述信息与安排」「以试点实测为准」「除特别说明外」）；
   - **不手写章号与节号**：`一、` / `（一）` / `1.` / `1.1` 都不写，交给 Word 自动编号；
   - 分条不用「一、二、」式编号（那是章号），用「第一 / 其一 / 目标一 / ①」或 `a) b) c)`。
8. **口径与量的处理**：
   - **数字要带口径**：写「8 个关键业务环节」「九件套（户内报警器、流量计…九个关键设备）」「第1—2个月」「四层架构 + 一脑一平台」——数字旁边就说清它数的是什么；
   - **金额与数量以参照件写法为准**：参照件写「预计 181 万元」「合计约 481 万元」「预计资金需求 2900 万元」「6 台（1 台/公司）」「80 台（1 台/氩弧焊工）」——金额带「预计/约」，台数带配置口径；
   - **材料里没有的金额与台数一律不编**，写「待客户提供」或「待现场勘查确定」，并把口径写在旁边（如「设备台数待现场勘查按班组数确定」）；
   - 型号与术语首次出现给一句限定（如「AI 高清球机（危险作业全过程视频监控）」）。

### 第 2 章 建设目标与思路（`goals`）

| 小节 | 写什么 | 形式 |
|---|---|---|
| `### 总体目标` | 一句话，格式是「以"…、…、…、…"为总体目标，构建覆盖＜对象＞的＜体系名＞，将管控重心由事后追责转向事前预防（预警）、事中控制、事后可溯，全面提升＜管理对象＞的安全质量管理水平」。参照件用词：燃气工程「本质安全、数据驱动、过程留痕、闭环管控」；工商户「状态可知、数据驱动、本质安全、闭环管控」。**四个引号内的短语是口号式提法，照抄这个句式即可，不要自由发挥成长段** | 正文 1 段（91 / 136 字） |
| `### 分项目标` | **2–4 条**，每条**一句结论式**：「对＜对象＞实现＜结果＞。＜支撑手段一句话＞」——参照件：燃气工程 3 条（`对物的不安全状态实现源头管控。` / `对人的不安全行为实现全程可溯。` / `以关键过程数据为核心资产，贯通多方协同，…`）；工商户 3 条（`1.对设备状态实现本质感知。` `2.对用气状态实现智能研判。` `3.以状态数据为核心资产，贯通多方协同。`）。**首句加粗（或作为条目标题），后面跟一到两句支撑** | 正文 3 段（分条不用「一、」，用「目标一 / 其一」或 `a)`） |
| `### 总体建设思路`（**可选**） | 「以"…为依托、…为基础、…为核心、…为目标"为总体建设思路」，再说清"感知—研判—结论—管控"这类闭环链路 | 正文 1 段（工商户 158 字；燃气工程件**没有这一节**） |

### 第 3 章 建设内容（`content`）

| 小节 | 写什么 | 形式 |
|---|---|---|
| `### 总体架构` | 先一句总纲：「本方案采用"四层架构 + 一脑一平台"的总体技术架构，包括感知层、传输层、平台层、应用层四个层级，以及＜AI 智能体中枢＞与＜统一协同平台＞两大核心枢纽。」再**一张分层表**。参照件里分层是**四层逐层一句**（感知层（神经末梢）/ 传输层（神经网络）/ 平台层（智慧大脑）/ 应用层（服务终端）），每层写"部署什么、采什么、传什么、给谁用"——本规格书要求把它**收进一张表**（见 §四 4.2），正文只留总纲一句，不再逐层复述 | 一句正文 + **1 表（自建，硬要求）** |
| `### 核心功能` | 先一句导语点出主线与项数（燃气工程：「以"物的不安全状态"与"人的不安全行为"两条核心主线为切入点，针对八个关键业务环节推行智能化管控」；工商户：「本部分为方案核心…按"通过什么手段、感知什么设备、得出什么结论"的逻辑主线」）。然后**按场景列 N 项**（参照件：燃气工程 8 项、工商户 9 件套分 4 类），**每项一段**，段落内部统一三段式：**管控/感知手段 → 感知什么（设备与数据） → 得出什么结论 / 预期成果**。导语后放**一张总览表**（见 §四 4.1 表①） | N 段 + **1 表（总览表）** |
| `### 状态研判与分级管控`（**可选**） | 平台怎么把上面的原始数据合成**结论**，再按结论分级：一段说研判模型与结论口径，一段说分级机制与管控频次差异，配**一张分级表**（见 §四 4.1 表②）。参照件口径：「风险越高、管控越严，状态越好、检查越简」；「数据研判—风险定级—频次匹配—闭环整改」 | 正文 1–2 段 + **1 表（写本节则硬要求）**（工商户 230 字 + 1 表；燃气工程件**没有这一节**） |

### 第 7 章 监管协同展望（`outlook`）

### 4.4 表格通用写法

- 表头用中文短名，一列一个概念；单元格写**结论与关键参数**，不写整句话（长说明放"用途/说明"列，允许一到两个短句）；

- 表格后空一行（`docs/Word输出规范.md` §6）；表内不加表号（内部表号禁写）；
- 一张表只承担一件事，不要把分层、设备、金额、计划挤进同一张表。

## 五、行文规范

1. **忌写成调研报告 / 总结**：不写"我们调研发现""经分析""综上""本次调研…"。方案是**已经定了怎么建**的陈述：现状章说今天怎么转与代价，建设内容章说建什么与怎么运作，建设路径章说数据从哪来、设备加什么、钱花在哪。
2. **每个数字都要带口径**：数"什么"、按什么范围数。写「八个关键业务环节」「九件套」「四层架构 + 一脑一平台」「第1—2个月」「1 台/公司」；孤零零一个数字（"涉及 8 个""投入 6 台"）算没写清。
3. **客户没给的数与钱一律不编，也不留占位（硬口径）**：金额、单价、台数、配置规模、覆盖率——这些都要客户自己评估，系统给不出来。**做法是这类列与这类话直接不写**（变更表 #138：成本表与「配置规模」列已删除），不要为它们造表、也不要逐格写「待客户提供」占位（真需要交代时，全章最多一句话）。参照件里已有的金额与台数照抄不改。
4. **不写决策建议**：`建议先 / 推荐 / 建议采用 / 推荐采用 / 值得投入 / 应当优先 / 不建议 / 可以决定`一律不出现。要推动的事写成安排（"由技术信息部在第 2—3 个月完成"），不写成建议。
5. **不出现内部痕迹**：表号（`表X-X`）、来源与页码、证据级与核实结论、`ingest-*`、缺口清单（"待补齐/信息缺口/无法核实"不得成串出现）。数据采集章里的"来源"是采集来源，正常写。
6. **不手写章号节号**：`一、` `（一）` `1.` `1.1` 都不写；分条用「第一 / 其一 / 目标一 / ①」或 `a) b) c)`。
7. **说人话**：不用"赋能 / 抓手 / 闭环"这类空话（"闭环"在"工单闭环处置"这种真流程里可用）；术语首现给一句限定（"全自动焊机（自动执行标准化焊接工艺并回传电流、电压、温度、压力、时间）"）。
8. **先结论后依据**：小节与段落开头一句就是结论，后面才支撑；单段 2–5 句；一个事实全篇只说一次。
9. **不写说明书腔与自证句**：不写「口径是…」「本节出现的数字…」「数据来源：…」「本方案只陈述…」「以试点实测为准」。要交代的口径直接写在数字旁边。
10. **加粗只用于条目首句**（分项目标、核心功能条目、编排要点），不强调句中词。
11. **标点**：中文全角；区间用 `—` 或 `~`（`第1—2个月`）；引号用「」或 `""`；顿号分隔并列项。
12. **术语与型号与场景口径一致**：沿用素材里的产品名与设备名（AR 采集终端、全自动钢管焊机、AI 高清球机、智能压力仪、无损检测数据回传终端、AI 智能阀、物联报警器…），**不要自己造型号**。

### 6.6 压缩守恒（只删不加）

某章正文超回炉线时让模型压一次——不许引入素材外信息、不许改数字与判定；删的是同一事实的重复、铺垫与过渡句、对表格的复述、形容词与套话、自我说明与免责；留的是结论、判断、代价、边界与表格本身；**表格原样保留**，`##` 章名与 `###` 小节标题一个都不能少、不许改名或合并；四张硬表必须还在；分条不许改成「一、二、」；不许留半句话。三种情形**作废这次压缩、保留原正文**（宁可偏长，不能缺构件）：构件变少；原本有 `###` 小节、压完一个小节都不剩；出现残句（短段落不以句末标点收尾）。

### 6.7 生成流程

1. 按章取素材 → 按章撰写（每块素材最多 12 行，归纳责任在模型）；
2. 确定性校验 → 有硬伤带违规清单**重写一次**；
3. 缺章**单独补写一次**；
4. 逐章篇幅回炉（超回炉线压一次，带 6.6 的守恒守卫）；
5. 装配：封面（`# <场景名称>建设工作方案` 一行）→ 七章（`---` 分隔，章名不带序号）；某章完全没写出来时用要点版兜底。**不追加附录、目录或术语表。**

### 8.2 建议新增的构件（现有四种不够用）

下一轮的候选（判定口径已写好，随时可落）：现有 `table` 只判"全文 ≥3 张表"，管不住"哪张表要有哪些列"：

| 建议名 | 判定口径 | 用在哪 |
|---|---|---|
| `device-table`（设备清单表） | 表头同时含「设备名称」与（`用途`/`主要用途`），数据行 ≥3 | 4 `### 新增感知设备` |
