# 场景会话体系技术方案（v2 · 产物唯一会话）

> 状态：已按用户评审意见收敛并进入实现<br>
> 日期：2026-10-23（v2）；替代同日 v1「多线程 / 会话工作台」方案<br>
> 范围：本地单用户桌面产品；左栏保持场景维度，右栏按**阶段产物**组织
> 一句话：**一个产物 = 一条会话；会话历史完整保留，压缩只发生在模型上下文里。**

---

## 1. 定调与边界

### 1.1 用户已确认的四条硬约束

1. **左栏不变化**：左栏仍然围绕场景，不出现会话列表、会话切换或「新建会话」。
2. **右栏以阶段产物为最小单元**：例如「认识场景」阶段的「分层架构」表。右栏的信息来源、备注、会话都属于这个产物。
3. **一个产物只有一条会话**：不管理多个会话，不提供会话列表、置顶、归档、分支、删除；打开产物就是继续这条会话。
4. **会话历史完整可见**：压缩只针对模型上下文，不删除、不折叠界面上的历史消息。

### 1.2 右栏布局

```text
┌ 右栏 ───────────────────────────────┐
│ 信息来源 8        备注 4             │  ← 两个页签，只属于本产物
│                                     │  （#296：阶段眉标/产物名/来源提醒数全删，
│                                     │    产物名只在会话区留一行）
├─────────────────────────────────────┤
│ 来源列表 / AI 结论与备注              │  ← 上区：可拖拽高度
│                                     │
├═════════════════════════════════════┤  ← 水平分隔条（鼠标/键盘可调）
│ 会话（唯一）                         │
│ 历史消息 …                           │  ← 下区：独立滚动
│ 「上下文已压缩 · 保留 N 条关键记忆」  │
├─────────────────────────────────────┤
│ [针对这个产物追问…]          发送     │  ← 固定在本产物底部
└─────────────────────────────────────┘
```

默认上区 30%、下区 70%；可拖到 22%–58%。拖动、`ArrowUp/Down`、`Home/End`、双击复位都可用，比例存 localStorage。

### 1.3 非目标

- 不做会话列表、全局搜索、收件箱、线程 fork、会话重命名/归档/删除。
- 不做第四栏，不把「场景定义」弹窗改成常驻聊天页。
- 不在本期引入多用户、云同步、团队权限。
- 不重写 DSH 的日志、工具循环与模型重试；模型上下文压缩先走确定性摘要，后续可平滑替换为 DSH compaction。

## 2. 产物模型

### 2.1 产物身份

一个产物由四元组唯一确定：

```ts
type ArtifactType = "anchor" | "table" | "deliverable";

interface ArtifactRef {
  step: number;              // 流程步 1–6
  stage: number | null;      // 数据阶段 0–5；交付物为 5
  type: ArtifactType;
  id: string;                // 表1-1 / 表2-3 / solution
  block?: string | null;     // 表内子块，如「分层架构」；不参与会话唯一性
  title: string;             // 用户看到的名字
}
```

会话唯一键为 `(scenario_id, step, type, id)`，**block 不拆会话**：同一张表的「分层架构 / 接口清单」共用一个讨论上下文，避免用户切块就丢记忆。

| 流程步 | 产物类型 | 产物 id 示例 |
|---|---|---|
| 1 场景定义与边界 | anchor | `表1-1` |
| 2 认识场景 | table | `表2-3` |
| 3 理解商业 | table | `表3-1` |
| 4 能力匹配 | table | `表4-1` |
| 5 方案与实现 | table | `表5-1` |
| 6 交付物 | deliverable | `solution` |

### 2.2 版本与失效

本期不新建一套产物版本表，沿用业务数据的 `updated_at` 计算**上下文指纹**：

- `context_hash = sha256(scenario_id|step|type|id|每行 id/updated_at/内容)`（交付物按各阶段总结的更新时间与内容长度）；
- 会话首次发消息时写入 `context_hash`；
- 读取会话时重新计算，与记录不一致即在右栏显示「产物已更新，新消息将基于当前内容」；
- 旧会话不清空、不重开，历史仍可回看；下一轮回答的上下文使用当前产物。

这与原型里的「基于 v3 / 当前 v4」是同一语义：**版本变化在会话里可见，但线程不断。**

## 3. 数据模型

在现有 `conversation` / `message` 上扩展，不新建第二套消息表。

```sql
ALTER TABLE conversation ADD COLUMN scope_type TEXT NOT NULL DEFAULT 'legacy';
ALTER TABLE conversation ADD COLUMN scope_id   TEXT NOT NULL DEFAULT '';
ALTER TABLE conversation ADD COLUMN step       INTEGER;
ALTER TABLE conversation ADD COLUMN block      TEXT;
ALTER TABLE conversation ADD COLUMN purpose    TEXT NOT NULL DEFAULT 'assistant';
ALTER TABLE conversation ADD COLUMN summary    TEXT NOT NULL DEFAULT '';
ALTER TABLE conversation ADD COLUMN context_hash TEXT NOT NULL DEFAULT '';
ALTER TABLE conversation ADD COLUMN last_activity_at TEXT;

CREATE UNIQUE INDEX ux_conversation_artifact_active
  ON conversation(scenario_id, step, scope_type, scope_id)
  WHERE kind = '产物会话' AND status = '活跃';
```

说明：

- `kind = '产物会话'` 的内部会话不进入左栏；左栏只显示 `kind = '用户'`（含旧数据缺省）。
- `scope_type = 'legacy'` 兼容旧会话，不参与唯一索引。
- `message` 仍是会话正文的落库真相；一条产物会话首次发消息时创建，打开面板不创建空会话。
- `summary` 保存最近一次上下文压缩的确定性摘要；`context_hash` 保存生成摘要时使用的产物指纹。
- 不复制可编辑正文到第二张表；UI 读取仍走 `message`。

### 3.1 为什么不用标题做唯一键

标题会随流程文案变化，且用户可改；用 `scope_type/scope_id/step` 才是稳定身份。标题只用于展示和调试。

## 4. 上下文与压缩

### 4.1 分层上下文

每轮发给模型的用户消息按以下顺序拼装：

| 层 | 内容 | 来源 |
|---|---|---|
| L1 | 当前场景、流程步、产物名、子块 | `scenario` + `ArtifactRef` |
| L2 | 本产物当前内容（最多 30 行，逐行字段摘要） | `stage_data` / 表1-1 / 交付物摘要 |
| L3 | 本步阶段总结与真实调研来源（最多 12 条） | `stage_summary` + `research_source` |
| L4 | 压缩摘要 + 最近对话 | 按 `message` 当前全量重算（`conversation.summary` 落库供审计） |
| L5 | 本轮用户消息 | 请求体 |

原则：**能由 L2/L3 结构化给出的，不把整篇材料塞进 prompt；能引用表行的，不复制全文。**

### 4.2 压缩策略

本期不调用模型生成摘要，使用确定性压缩，保证可测试、零额外成本：

1. 最近 `12` 条消息、总量 `6000` 字符进入完整历史（沿用现有预算）。
2. 更早的消息按「决策 / 约束 / 未决 / 对话」分类，**先取关键记忆、再拿普通对话补位**，同类取较新的，最多 12 条、每条截 `120` 字，按时间顺序写入 `【更早对话摘要】`。
3. 摘要同时写入 `conversation.summary`；UI 在发生压缩时显示：
   `上下文已压缩 · 保留 N 条关键记忆`，可展开查看摘要。
4. 摘要保留「决策 / 约束 / 未决 / 对话」四个前缀，便于下一轮模型区分事实、约束与待办；不调用模型，保证可测试、零额外成本。

后续接入 DSH compaction 时，只替换 `compactHistory()` 的实现，数据字段与 UI 不变。

## 5. API

所有接口在 `/api/v1` 下，沿用现有 SSE 事件格式（`text / done / error`）。

### 5.1 读取产物会话

```http
GET /projects/:id/artifacts/thread?step=2&type=table&id=表2-3&block=分层架构&title=分层架构&stage=1
```

响应：

```json
{
  "conversation_id": null,
  "messages": [],
  "summary": "",
  "compacted": false,
  "kept": 0,
  "stale": false,
  "artifact": { "step": 2, "type": "table", "id": "表2-3", "title": "分层架构" }
}
```

打开不创建会话：`conversation_id` 为 `null` 时 UI 显示空态。首次发送才创建。

### 5.2 发送消息

```http
POST /projects/:id/artifacts/thread/messages
{ "step": 2, "type": "table", "id": "表2-3", "block": "分层架构", "title": "分层架构", "stage": 1, "content": "为什么中控主机放平台层？" }
```

- 服务端 `ensureArtifactConversation()`：按唯一键找活跃会话，没有才创建（含 DSH session）。
- 用 `buildArtifactContext()` 生成本产物上下文，作为 `contextPrefix` 传给现有 converse 管道。
- 通过 SSE 返回增量；结束后更新 `last_activity_at`、`context_hash`、`summary`。
- 前端 `sending` 锁避免同一窗口重复提交；桌面端单窗口使用。多窗口同时发同一产物仍会追加到同一条会话（P2 再做服务端串行化）。

### 5.3 续传

```http
GET /projects/:id/artifacts/thread/events?step=…&type=…&id=…&lastEventId=…
```

按运行键回放本进程缓存的 SSE 事件；重启后历史消息仍可从 `GET thread` 取回。

## 6. 前端接线

### 6.1 产物切换

- `RealStagePanel` 把当前 `activeTable / block` 写入 `StageSnapshot.artifact`；
- `AnchorStepPanel` 固定为 `表1-1`；
- `DeliveryPanel` 固定为 `solution`；
- `ArtifactRightPanel` 只认 `snapshot.artifact`，产物变化即重新拉取该产物的会话；旧 `StageRightPanel` 已删除，`renderMarkdown` 抽到 `render-markdown.tsx`，仅供交付物报告渲染。

### 6.2 新建场景

- 新建仍走现有 `NewScenarioDialog`；
- 创建成功后打开「场景定义」弹窗（既有行为），关闭后回到流程第 1 步；
- 右栏此时定位 `表1-1`，会话为空态，不自动创建会话；
- 取消新建则停留在原场景/原产物，不改变右栏状态。

### 6.3 保留的现有能力

- 「调研信息来源」与「结论提醒」继续用已有 `StageSnapshot.brief`，不重新造数据；
- 零来源时自动补查一次、手动「补跑本步调研」保持；
- 演示模式仍显示本地说明，不发请求。

## 8. 验证标准

| 项 | 标准 |
|---|---|
| 唯一性 | 同一产物反复打开/发送，始终只有一条活跃会话 |
| 左栏 | 不出现「产物会话」；场景列表/导航不受影响 |
| 历史 | 发送 20 轮后，界面仍能看到全部消息；模型上下文只带摘要 + 最近 12 条 |
| 切换 | 表 A → 表 B → 表 A，各自消息不串；block 变化不新建会话 |
| 版本 | 表格内容更新后，右栏显示「产物已更新」，旧消息保留 |
| 分栏 | 鼠标拖动、方向键、Home/End、双击复位均生效，刷新后比例保留 |
| 空态 | 未发送时 `conversation_id=null`，不产生空会话 |
| 新建 | 新建后右栏回到 `表1-1`；取消不改变当前产物 |

## 9. 选型说明（沿用 v1 调研，不重复展开）

- 会话内核继续用 DeepSeek Harness 的 session/模型适配能力；产品侧只做产物作用域、上下文、压缩与 UI。
- 不自研通用聊天产品壳：本产品管理的是「围绕一份会变化产物的决策过程」，不是「会话列表」。
- 不引入 assistant-ui 等聊天 UI 依赖：现有三栏与设计 token 已足够，避免第二套视觉体系。
