# 01 产品介绍与目标用户

## 1.1 一句话

**场景通是给解决方案架构师用的桌面 AI 智能体：接一个客户场景，从材料入库、场景定义，到 6 步分析、26 张信息表，最后产出可讲的《解决方案》和 PPT 大纲，把“这场景能不能进、怎么进、值不值”的调研从几周压到几天。**

它不是一个“帮你写文档”的聊天框，而是把售前调研这件事拆成可执行步骤、把每一步的信息结构化和可溯源、最后自动收口成可交付文件的垂直产品。

## 1.2 产品是什么

| 维度    | 说明                                                    |
| ----- | ----------------------------------------------------- |
| 形态    | macOS / Windows 桌面应用，安装后本机运行；不是网页 SaaS                |
| AI 底座 | DeepSeek Harness（DSH）Agent 会话 + 可切换的模型供应商；模型负责内容生成与推理 |
| 数据    | 场景、资料、交付物全部存本机；默认不上传客户材料                              |
| 核心工作流 | 6 步：场景定义与边界 → 认识场景 → 理解商业 → 能力匹配 → 方案与实现 → 交付物        |
| 信息载体  | 26 张结构化信息表；逐格可编辑、每行可标来源                               |
| 交付物   | 《XX场景解决方案》＋ PPT 大纲；可导出 Word / PPT / Markdown          |
| 常驻资产  | 产品资料库（产品清单、规格书、能力、边界、报价、认证/案例等）；跨场景复用                 |

## 1.3 目标用户

### 主用户：解决方案架构师 / 售前方案工程师

| 项    | 说明                                     |
| ---- | -------------------------------------- |
| 角色   | 系统集成商、设备厂商、行业解决方案公司的售前/方案架构师           |
| 日常任务 | 接客户场景 → 判断能不能做 → 组织调研 → 写方案 → 给客户/领导汇报 |
| 使用场景 | 新客户/新行业场景的前期调研；投标前方案准备；存量客户的新场景扩展      |
| 最痛的点 | 信息散、调研维度容易漏、来源说不清、每次重做、方案写作耗时          |

### 次用户：售前负责人 / 部门管理者

- 看团队产出的《解决方案》是否客观、有依据、能直接对客户讲；
- 决定是否投入某个场景，而不是自己从零做调研；
- 关心团队复用率、交付周期和方案质量的一致性。

### 不在目标范围内

- 个人日常写作、会议纪要、通用问答等“个人提效工具”；
- 替客户做最终商业决策的“决策系统”；
- 只做知识库检索、不产出结构化调研与交付物的问答机器人。

## 1.4 典型使用场景（一条完整故事）

1. 架构师接到客户“智慧会议室”需求，手里有客户招标文件、我方产品白皮书、历史案例；
2. 打开场景通，把客户材料上传到当前场景，把我方产品资料放进产品资料库；
3. 新建场景，AI 先讲清这类场景的行业背景，再问 2–3 个关键问题，整理成场景定义；
4. 按 6 步推进：AI 联网调研 + 生成各步信息表，架构师逐格校对、补来源；
5. 每一步右栏有一份阶段总结，随时能看“这一步到底得出了什么”；
6. 最后生成《解决方案》和 PPT 大纲，架构师改完直接导出 Word/PPT，拿去汇报。

## 1.5 核心能力

1. **场景化，不是通用问答**：所有分析围绕一个具体客户场景和一套方法论展开，不靠用户自己想 prompt。
2. **结构化信息**：26 张表把“该看什么”固定下来，避免漏掉合规、竞争、能力边界、交付运维等维度。
3. **来源可追溯**：每条结论可标来源（文件/页码/URL）、权威性 T1–T4、证据等级 A–D；查不到就写“未知”，不编。
4. **AI 原生闭环**：AI 承担场景理解、调研、表格生成、方案与大纲撰写；确定性层只做质量门禁，不替代内容生成。
5. **交付物收口**：不是停在表格，最后产出解决方案 + PPT 大纲，并能导出 Word/PPT/Markdown。
6. **本地与复用**：产品资料库跨场景复用；数据在本机，适合客户材料不便上云的售前场景。

## 1.6 和通用 AI / 通用知识库的区别

| 对比  | 通用大模型/Agent | 通用知识库   | 场景通                    |
| --- | ----------- | ------- | ---------------------- |
| 输入  | 用户自己描述问题    | 上传文档后问答 | 客户场景 + 我方产品资料          |
| 过程  | 一次性对话       | 检索 + 回答 | 6 步方法论 + 26 张表 + 阶段总结  |
| 输出  | 一段文本        | 一段回答/引用 | 结构化信息 + 解决方案 + PPT 大纲  |
| 来源  | 不稳定、常编      | 有引用但不分级 | 来源 + 权威性 + 证据等级，缺来源标未知 |
| 复用  | 无           | 文档级     | 产品资料库跨场景复用             |
| 数据  | 云端          | 云端/私有化  | 本机桌面，默认不上传             |

## 1.7 产品边界

- **不替用户做最终决策**：产品给信息、给建议、给方案，进不进、投不投由用户拍板。
- **不保证“什么场景都能做”**：能力缺口、资质门槛、价格劣势会如实进表，不靠话术掩盖。
- **不把模型知识当来源**：没有可核验来源的内容标“未知”，不用行业通例冒充客户事实。
