# 03 价值量化

> 场景通 · L1 产品文档（3/6）
> 状态：提交稿 v0.1
> **重要说明**：本文给出指标口径、测算公式与待补基线；除标注“产品事实”外，所有数字都必须用真实项目/访谈替换，**不得把示例假设写成实测结果**。

## 3.1 价值主张

场景通的价值不是“多一个 AI 工具”，而是把售前调研从**个人经验驱动**变成**可复用的团队流程**：

1. **更快**：一个客户场景从材料到可讲方案，周期从“周”降到“天”；
2. **更全**：6 步流程 + 26 张表，合规、竞争、能力边界、交付运维等维度不漏；
3. **更可信**：每条结论有来源/权威性/证据等级，查不到就写未知；
4. **更省**：产品资料库跨场景复用，不再每次重做；
5. **更一致**：解决方案与 PPT 大纲由同一套信息生成，团队产出质量更稳定。

## 3.3 基线怎么测（11-11 前可完成的最小方案）

### 方法 A：一个真实项目的回顾性对比（最省时）

选一个最近完成的真实场景，找参与架构师做 30 分钟访谈，按表填：

| 问题 | 记录 |
|---|---|
| 这个场景从接到需求到方案可讲，花了几个自然日？ | |
| 几个人参与？各投入多少人天？ | |
| 收集/整理材料花了多久？ | |
| 调研/分析花了多久？ | |
| 写 Word/PPT 初稿花了多久？ | |
| 返工几次？每次因为什么？ | |
| 哪些信息最后没找到来源？ | |

### 方法 B：新项目实测（更可信，但需要 1–2 周）

用场景通跑一个**新场景**，记录：

- 开始时间、每步完成时间、交付物导出时间；
- AI 生成后人工修改的单元格数/行数；
- 使用的来源条数、无来源的“未知”条数；
- 与回顾性基线对比周期、人天、写作时间。

### 方法 C：3 人访谈（补用户价值证据）

找 3 位架构师，每人问 5 个问题：最痛的环节、现在花多久、最常漏什么、方案被退回的原因、愿意为什么付费。

> 提交版至少做 A + C；有条件做 B。没有基线的数字不要写。

## 3.4 测算公式

### 3.4.1 人天节省

```
月节省人天 = 月场景数 × (人工单场景人天 − 场景通单场景人天)
年节省成本 = 月节省人天 × 12 × 人天成本
```

### 3.4.2 周期缩短

```
周期缩短率 = (人工周期 − 场景通周期) ÷ 人工周期
```

### 3.4.3 复用价值

```
复用节省 = 复用场景数 × 单场景材料整理人天 × 人天成本
```

### 3.4.4 ROI（对客户）

```
ROI = (年节省成本 − 年工具成本) ÷ 年工具成本
```

## 3.5 示例演算（**假设示例，不是实测**）

> 下面只用于说明怎么算，提交前必须替换成真实基线；不得把这段当结果。

假设一个 5 人售前团队：

- 每人每月 2 个新场景 → 10 个场景/月；
- 人工：单场景 8 人天（材料 1 + 调研 3 + 方案 4）；
- 场景通：单场景 2 人天（材料 0.5 + 校对 1 + 交付物 0.5）；
- 人天成本 1,500 元。

则：

```
月节省人天 = 10 × (8 − 2) = 60 人天
月节省成本 = 60 × 1,500 = 90,000 元
年节省成本 ≈ 1,080,000 元
```

如果工具定价为每席位每年 1–2 万元，5 人团队年成本 5–10 万元，ROI 约 10–20 倍。

**这段数字全部是假设**；真实提交时替换为访谈/实测值，并写清样本量和口径。

## 3.6 价值证据怎么放进 Demo/文档

1. 产品文档第 3 章放**一张基线表 + 一张前后对比图**；
2. 视频最后 20 秒用一句话点出“周期/人天/来源覆盖率”三个数字；
3. 附录放访谈记录（匿名）与测算表，评委会看“数字怎么来的”。

## 3.7 现在能确认的产品事实

- 一个场景从材料到交付物，全部在一个应用内完成，不需要在 Word/Excel/浏览器之间来回搬；
- 解决方案与 PPT 大纲由同一次生成产出，不需要二次整理；
- 产品资料库跨场景复用，场景级覆盖不污染主库；
- 来源/权威性/证据等级随行记录，导出时保留；
- 本地数据，不上传客户材料。
