# 02 需求背景与痛点

## 2.1 背景：售前调研是方案团队的固定瓶颈

系统集成商、设备厂商和行业方案公司的售前架构师，接到的不是“写一份文档”，而是一个需要判断的客户场景：

- 这个场景客户到底怎么买、预算在谁手里？
- 有哪些硬门槛（资质、合规、接口、交付）？
- 现在谁在供、价格什么水平、我们有没有赢面？
- 如果要做，方案怎么落、交付运维怎么兜？
- 最后怎么快速变成一份能对客户讲的方案？

这套判断依赖大量信息，但信息天然分散、来源复杂、更新快。多数团队靠“老架构师的经验 + 临时搜索 + 拼文档”，结果高度依赖个人，难以复用，也难以保证质量。

## 2.2 痛点清单

### 痛点 1：材料散落在邮件、网盘、聊天记录里

- **怎么发生**：客户招标文件在邮箱，产品白皮书在共享盘，历史案例在个人电脑，竞品价格在聊天记录；没有一个按“场景/产品线”组织的入口。
- **影响谁**：架构师（找材料）、售前负责人（无法确认团队用的是什么版本）、新同事（上手慢）。
- **现在怎么应对**：每次重新收集；找到什么用什么；版本不一致时靠人记。
- **代价**：重复收集、漏材料、用错版本；一个场景启动的前 1–2 天常常花在找材料上。

### 痛点 2：不知道该看什么，调研维度容易漏

- **怎么发生**：行业调研没有固定骨架，合规、竞争、上游供给、交付运维、价值指标这些维度，靠个人经验决定查不查。
- **影响谁**：架构师（漏项导致方案被客户问倒）、售前负责人（方案质量参差）。
- **现在怎么应对**：老同事带新人；临时列提纲；参考上一份方案改。
- **代价**：同一个场景不同人做出来差异很大；合规/交付类硬约束常在方案后期才暴露，返工成本高。

### 痛点 3：来源不可追溯，结论被追问时站不住

- **怎么发生**：调研结论来自网页、报告、聊天或“行业常识”，没有记录出处；客户追问“这个数字哪来的”时答不上。
- **影响谁**：架构师（可信度受损）、公司（方案风险）。
- **现在怎么应对**：凭记忆解释；临时再搜；把“行业通例”当客户事实。
- **代价**：方案可信度低；错误数字进入报价/承诺；严重时影响投标。

### 痛点 4：每接一个场景就重做一遍

- **怎么发生**：产品能力、案例、认证、报价是全局资产，但每次做新场景都重新收集、重新整理；同一产品线的材料在不同项目里重复上传。
- **影响谁**：架构师、产品经理、售前团队。
- **现在怎么应对**：个人维护自己的资料夹；团队共享盘靠人工同步。
- **代价**：重复劳动；资料越用越散；新人无法复用老人的积累。

### 痛点 5：方案写作耗时，且质量不稳定

- **怎么发生**：调研做完后，要把信息组织成“现状—问题—方案—价值—实施”的文档；不同人写出来结构、详略、口径都不同。
- **影响谁**：架构师（加班写方案）、负责人（审稿成本）。
- **现在怎么应对**：套模板、复制旧方案、让同事帮忙改。
- **代价**：单份方案写作 1–3 天；模板痕迹重；客户视角弱。

### 痛点 6：调研过程沉淀不下来

- **怎么发生**：调研结论留在个人文档或脑子里；下一个场景无法复用；竞品、价格、未满足需求没有进入团队资产。
- **影响谁**：团队、管理者。
- **现在怎么应对**：靠人传、靠复盘会、靠共享盘。
- **代价**：人员流动即资产流失；团队整体能力提升慢。

## 2.3 现有替代方案为什么不够

| 替代方案                | 能做什么      | 不够在哪                          |
| ------------------- | --------- | ----------------------------- |
| 人工调研 + Word/PPT     | 灵活、可定制    | 慢、依赖个人、来源不可追溯、难复用             |
| 通用大模型/Deep Research | 快速给一段分析   | 不懂我方产品、不产结构化表、来源不稳定、无法直接形成交付物 |
| 通用知识库/办公 AI         | 检索文档、回答问题 | 只解决“找得到”，不解决“该看什么、看全没有、怎么成方案” |
| 咨询/行业研究报告           | 有行业深度     | 贵、周期长、不针对具体客户场景、不落到我方能力       |
| CRM/售前管理工具          | 管商机/流程    | 不管调研内容，不生成方案                  |

## 2.4 场景通的对应解法

| 痛点     | 场景通的解法                        | 落地位置         |
| ------ | ----------------------------- | ------------ |
| 材料散    | 产品资料库按产品线组织，场景引用；材料一次入库、跨场景复用 | 产品资料库 + 场景项目 |
| 维度漏    | 6 步流程 + 26 张信息表，把“该看什么”固化成骨架  | 流程与表定义       |
| 来源不可追溯 | 每条信息可标来源/权威性/证据等级；没有来源标“未知”   | 来源与证据模型      |
| 重复做    | 产品资料库复用；场景级覆盖不污染主库            | 资料库与场景引用     |
| 方案写作慢  | 阶段总结 + 解决方案 + PPT 大纲自动生成      | 交付物          |
| 沉淀不下来  | 调研结果落库；产品资料与场景资产持续累积          | SQLite 本地库   |

## 2.5 真实场景

以上痛点不是推演出来的，是在真实售前场景里反复出现的：

- 已用场景通跑过智慧会议室、智慧教室、地铁能源管控、管网阀室、智慧厨房等真实场景，走完从材料入库、场景定义到 6 步分析、解决方案与 PPT 大纲的完整链路；
- 这些场景里有客户招标文件、产品白皮书、历史案例、竞品信息等真实材料，材料散、来源杂、需要反复核对的问题都出现过；
- 本文不写客户名称、金额和项目细节；提交版用匿名场景 + 可核对的内部记录说明“真实发生过”。
