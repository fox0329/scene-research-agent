## 6.1 工程总览

场景通是“桌面壳 + 本机服务 + 本地库 + AI 引擎”的单机应用：

```
Electron 桌面壳（macOS / Windows）
  ├── React + Vite 前端（三栏工作台）
  ├── Fastify 本机服务（127.0.0.1，随机端口）
  │     ├── 应用层：场景/流程/表格/对话/交付物/导出
  │     ├── 领域层：判定、校验、质量门禁（纯 TS，可单测）
  │     └── 基础设施：SQLite、文档解析、DSH 客户端
  └── 本地数据目录（场景、资料、交付物、日志）

AI 引擎：DeepSeek Harness（DSH）Agent 会话 / OpenAI 兼容模型
```

关键工程选择：

| 选择 | 原因 |
|---|---|
| 桌面应用，不是网页 SaaS | 客户材料敏感，本地存储、本地服务，数据默认不出机器 |
| 本机 Fastify + 随机端口 | 不暴露公网；只绑 127.0.0.1；桌面壳负责启动/健康检查 |
| SQLite（better-sqlite3） | 单机单人，无需数据库服务；事务与迁移简单 |
| DSH Agent 会话 | 支持工具调用、流式输出、断点续做；模型可切换 |
| 确定性领域层 | 来源/数字/结构/质量门禁可单测，不把判定交给模型 |
| 契约共享（TypeScript） | 前后端同一套类型，26 张表结构单一事实源 |

## 6.2 端到端流程

```mermaid
flowchart LR
  A[上传客户材料/产品资料] --> B[解析入库]
  B --> C[新建场景]
  C --> D[AI 场景定义对话]
  D --> E[表1-1 场景锚]
  E --> F[6 步分析: 检索→生成→校验]
  F --> G[26 张信息表]
  G --> H[阶段总结]
  H --> I[解决方案 + PPT 大纲]
  I --> J[导出 Word/PPT/Markdown]
```

每一步的 AI 调用都带：

- 系统提示：角色、当前步骤、目标表结构、质量要求、禁止事项；
- 用户输入：场景锚、上游表、材料摘要、检索结果；
- 输出契约：JSON/表格结构，服务端校验后落库；
- 失败策略：重试、降级、保留旧内容、提示用户。

## 6.3 AI 能力落点（逐项）

| # | 能力 | 模型/能力 | 输入 | 输出 | 失败兜底 |
|---|---|---|---|---|---|
| 1 | 场景定义 | 对话 + 行业知识 | 场景名、用户回答、材料 | 行业说明、关键问题、表1-1 | 问不出就按用户输入整理，标“系统推断” |
| 2 | 联网调研 | Agent + web 工具 | 场景/步骤/实体 | 来源列表 + 正文摘要 | 无来源写“未知”，不编 |
| 3 | 表格生成 | 结构化输出 | 场景锚、上游表、材料、来源 | 26 张表的行/列 | 字段不合法修正/丢弃，提示原因 |
| 4 | 阶段总结 | 归纳生成 | 本步表格 | 右栏总结文档 | 生成失败保留表格，可重试 |
| 5 | 解决方案 | 长文生成 | 全链表格/总结 | 七章 Markdown | 分章重试/兜底，不产空文件 |
| 6 | PPT 大纲 | 结构化生成 | 解决方案正文 | 6–15 页大纲 | 失败不推翻解决方案，可重生成 |
| 7 | 对话改表 | 工具调用 | 用户自然语言 + 当前表 | 单元格更新 | 找不到目标就反问，不猜 |
| 8 | 导出 | 确定性渲染 | 正文/大纲 | docx/pptx/md | 失败给原因，不产生半文件 |

## 6.4 关键工程实现

### 6.4.1 Agent 运行时

- 消息日志：system + user + assistant tool_calls + tool results；
- 多步循环：模型可连续调工具（读表、写表、检索、保存），最多 N 步，重复调用去重；
- 工具结果回喂：模型根据结果决定继续/修正/收口；
- 流式输出：SSE 推进度，前端可续连；
- 失败反馈：工具错误作为 tool 消息回给模型，不直接中断。

### 6.4.2 结构化输出与校验

- 契约定义 26 张表的列、必填、长度、枚举；
- 模型输出 JSON → 服务端解析 → 领域层校验 → 非法行修正/丢弃并提示；
- 关键数字与来源做确定性比对；
- 质量门禁在导出前逐条跑，问题点名到页/行。

### 6.4.3 来源与证据

- 来源类型：材料文件（文件名 + 页码）、URL（标题 + 日期）、用户输入；
- 权威性 T1–T4、证据等级 A–D；
- 没有来源 → 写“未知”，不拿模型知识冒充；
- 来源索引与全文检索（SQLite FTS）。

### 6.4.4 本地数据与安全

- 数据目录：macOS `~/Library/Application Support/@scene/desktop/data/`；Windows `%APPDATA%\@scene\desktop\data\`；
- 服务只绑 `127.0.0.1`，随机端口；
- 模型 Key 应用内配置，本地保存；
- 客户材料与业务数据存本机，不建云端知识库；只有模型调用所需的摘要/片段发给配置的模型端点；
- 日志脱敏，不记录 Key。

### 6.4.5 交付与打包

- Electron 36 + electron-builder；
- macOS Apple 芯片 dmg；Windows x64 setup；
- Windows 安装包内置 PPT 组件（Python + ppt-master 脚本），装完可导出 PPT；
- GitHub Actions 双平台构建 + 真启动冒烟 + 打包冒烟；
- 版本 0.9.4。

### 6.4.6 质量验证

- 单元测试：108 文件 / 1,998 例；
- E2E：51 例（真实服务 + 浏览器）；
- 类型检查 0 错误；
- CI：macOS / Windows 各自构建、启动、检查数据库与页面。

## 6.5 PRD 摘要

### 产品目标

让解决方案架构师在一个桌面应用内完成“客户场景调研 → 结构化信息 → 可讲方案”的闭环。

### 核心用户故事

1. 作为架构师，我上传客户材料后，AI 能先理解场景并问我关键问题，而不是让我填 26 张表；
2. 作为架构师，我按 6 步推进，每一步 AI 先给初稿，我能逐格校对并看到来源；
3. 作为架构师，我能在右栏用自然语言改表，中栏立即更新；
4. 作为架构师，我最后能一键生成解决方案和 PPT 大纲，并导出 Word/PPT；
5. 作为售前负责人，我能看到方案里的每条结论有来源，没有来源的标“未知”。

### 功能范围（v0.9.4）

- 产品资料库：上传/解析/去重/跨场景引用；
- 场景项目：新建/重命名/归档/删除；
- 场景定义对话；
- 6 步流程与 26 张表；
- 右栏对话改表、阶段总结；
- 解决方案 + PPT 大纲 + 导出；
- 模型配置、安装/升级、本地数据。

### 非目标

- 不做 CRM/商机管理；
- 不做标书排版/查重；
- 不替用户做最终决策；
- 不做多租户 SaaS（当前版本）。

### 验收口径

- 安装可启动、数据不丢；
- 6 步能走完，表可编辑，来源可追溯；
- 解决方案/PPT 大纲能生成并导出；
- 关键错误有提示，不白屏/不静默丢数据。

## 6.6 关键流程图与原型

- 端到端流程：见 6.2；
- 三栏工作台：左栏场景/资料库，中栏当前步表格，右栏对话/来源/阶段总结；
- 关键界面：场景定义弹窗、6 步流程轴、表格编辑、右栏对话、交付物页签（解决方案 / PPT 大纲）；
- 原型与设计规范：`docs/技术方案-场景会话体系.md`、`场景通-prototype-v10.html`（历史原型，现行以工程为准）。

## 6.7 已知限制（诚实披露）

1. 安装包未签名：macOS 首次需右键打开，Windows SmartScreen 需“仍要运行”；
2. 无内置备份/恢复：升级前需手动复制数据目录；
3. 重复入库按行去重，模型重抽的值变体会保留原值并提示冲突；
4. PPT 导出依赖本机/内置组件；Windows 0.9.2 起已内置；
5. 联网调研受目标站点反爬/网络影响，失败时如实标“未知”，不伪造来源。
