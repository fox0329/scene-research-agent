# 技术调研：以客户 PPT 模版为质量基线（PPT 大纲与生成要求重写）

- 日期：2026-10-21
- 触发：用户提供 `PPT模版.pptx`，要求「参照模版重新优化 PPT 大纲生成的要求和 PPT 生成的要求，以模版为基准，生成的 PPT 质量不能低于模版」
- 结论落地：`packages/contract/src/ppt.ts`（`PPT_TEMPLATE` 令牌）、`packages/infra/src/ppt-svg.ts`（渲染）、`packages/infra/src/ppt-quality.ts`（门禁）、`packages/domain/src/ppt-outline.ts`（解析与结构判据）、`apps/server/src/ppt-prompt.ts`（提示词）

## 一、现状：模版长什么样（实测，不是印象）

用 python-pptx 直接读模版（`/Users/lizhongliang/PPT模版.pptx`，6 页，13.33×7.5 in），逐项量出来：

| 维度 | 实测值 | 我们改之前 |
|---|---|---|
| 标题 | **24pt 加粗 `#1D2A8C`**，位置 (0.48–0.51, 0.36) in，左上顶格 | 27pt，(0.8, 0.7) in |
| 强调副题 | **16.5pt 或 20pt 加粗**，`#0070C0` / `#055CDD` | 18px 常规灰 |
| 正文 | **11.25pt** `#404040` | 12pt（16px） |
| 页脚 / 微标 | **10.5pt** `#7A7A7A` | 12px，左「场景通 · 场景」、右无页码 |
| 页码 | 页脚右侧 **`NN / MM`** | 右上角「第 N 页 / 共 7 页」胶囊 |
| 小节标签 | 无胶囊，只有一行小字（部分页有小图标） | 左上浅蓝胶囊 + 22px 图标 |
| 每页文字条数 | **29–57 条**（内容页） | 20–32 条 |
| 页面结构 | 6 页 5 种结构：封面（4 能力卡 + 3 步链 + 6 标签 + 一句话）/ 枢纽图 / 五层能力栈 / 4×4 能力矩阵 / 路线图 / 三支柱 | 7 页内容页，结构以「网格要点」为主 |
| 封面 | **有，而且写满**：标题 + 四张能力卡（图标 + 中文名 + 英文小标 + 两行说明）+ 三步落地链 + 落地版本标签 + 一句话总结 | 明文规定「不要封面」（变更表 #141） |

**关键判断**：我们和模版的差距不是"配色不好看"，而是三件事——① 字号体系偏大、层级少；② 每页信息密度低一档（模版 29–57 条 vs 我们 20–32 条）；③ 没有封面，且页面结构单一。这三条都是**可量化、可判据化**的，所以做成了令牌 + 门禁，而不是"感觉像一点"。

## 二、业界做法与我们的选择

| 候选做法 | 业界现状 | 我们的选择与理由 |
|---|---|---|
| A. 交给模型端到端出 PPT（LLM → pptx 直出） | 主流 AI PPT 工具（Gamma、Tome、islide AI 等）走「模板 + 模型填内容」，模板约束越强、输出越稳；纯模型直出在字体、对齐、密度上不可控 | **不采用**。我们已有确定性 SVG 渲染 + ppt-master 转档，模型只写大纲内容；把模版的**度量**变成渲染器常量与门禁阈值，输出与模型无关地稳定 |
| B. 只用提示词描述"照模版的样子" | 常见做法，但"像模版"没有判据，模型每轮差异大，回归无基线 | **不采用单靠提示词**。提示词与判据同源：`PPT_TEMPLATE` 一处定义，提示词引用、渲染引用、门禁引用（单测断言三者一致） |
| C. 令牌 + 判据 + 提示词三处同源（选中） | 设计系统领域的成熟做法（design tokens → lint rules → generation spec） | **采用**。模版实测值落成 `PPT_TEMPLATE`（颜色/字号/边距/页脚格式），渲染器按令牌画、门禁按令牌判、提示词按令牌写，改模版只改一处 |
| D. 直接把模版当母版套用（python-pptx 改模板占位符） | 能保证视觉一致，但模版页数、结构与内容语义强绑定，换场景就要改母版；且我们走 ppt-master 的 SVG 通路 | **不采用**。模版作为**质量基线**而非母版：结构类型对齐（封面/矩阵/栈/路线图/对比/数字），版式仍由确定性渲染器生成，任何场景可复用 |

**创新点（明确说）**：把"以模版为基准"从审美要求变成**可执行判据**——模版的字号、密度、页脚格式、结构多样性全部落成常量与门禁（缺封面 / 版式单一 / 版式重复 / 每页 ≥16 条 / 字号 ≥15px），模型每一轮都要过这些判据。这不是"把模版抄一遍"，而是"把模版翻译成机器能守的线"。业界同类工具多以模板渲染为主、缺少对**生成内容结构**的门禁，这一层是我们的差异。

## 三、落点（逐项）

1. **令牌**（`PPT_TEMPLATE`）：主色 `#1D2A8C`、强调 `#0070C0`/`#055CDD`、正文 `#404040`、弱化 `#7A7A7A`、页码灰 `#A8AEB8`、绿 `#22943A`；标题 24pt/32px、副题 16.5pt/22px、正文 11.25pt/15px、微标 10.5pt/14px；边距 0.48/0.36 in；页脚格式 `NN / MM`。
2. **渲染**（`ppt-svg.ts`）：新页眉（小节小字 + 32px 标题 + 22px 加粗副题 + 右对齐标签）、页脚（左产品行 + 右 `NN / MM`）、底部一句话总结（深灰一行，去掉旧结论带）；**新增封面渲染器**（2×2 能力卡 + 三步链 + 标签行 + 总结）；块行数 3–5、层 3–5×2–6、对比栏 2–3。
3. **门禁**（`ppt-quality.ts`）：字号下限内容 15px / 元信息 14px；每页文字 ≥12（结构件少的页面也要过）；图标 ≥3；新增 `缺封面`、`缺页码`，旧 `缺结论带` 改为 `缺一句话总结`；模板一致性由 `PPT_TEMPLATE` 驱动。
4. **大纲判据**（`ppt-outline.ts`）：`封面` 为合法布局（四张能力卡 + 三步链，缺一降级）；新增 `缺封面` / `版式单一` / `版式重复`；密度目标 16 条（门禁下限 12，因为卡片/表格结构上到不了 16）。
5. **提示词**（`ppt-prompt.ts`）：新增「模版基线」一节，把模版 6 页的 5 种结构逐条映射到我们的 8 种布局；写明封面必须写满、整份 ≥4 种结构、同种最多连 2 页、每页 ≥16 条；JSON 示例从 4 页扩到 5 页并含封面。

## 四、为什么推翻「不要封面与尾页」（变更表 #141）

#141 是"汇报 PPT 不要空扉页"的语境；模版给的是一张**信息密度等同内容页的封面**（4 能力卡 + 3 步链 + 标签 + 总结）。两者不矛盾：禁的是"只有标题的扉页"，要的是"第一页就说清四个卖点"。因此改为：**必须有封面，且封面必须写满**，尾页仍不做。这一条在变更表里登记为对 #141 的显式覆盖。

## 五、风险与回退

| 风险 | 处理 |
|---|---|
| 模型写不满 16 条 → 每轮都被点名 | 提示词给"写满模板"（4 块 × 3–5 行 / 5 层 × 2–6 组件）；结构上写不满的版式按"写满"算（`pptLayoutSentenceMax`）；三轮不过仍照常导出（不阻断），notice 点名 |
| 封面降级后第一页变普通页 | 降级保留内容（搬进要点行），门禁报 `缺封面` 进入下一轮；不静默丢页 |
| 模版实测值有主观成分（页码位置等） | 只把**可量化且影响观感**的项写死（字号/密度/页脚/结构），装饰性细节不入判据，避免把模版的一次性设计当成硬标准 |
| 旧测试大量依赖旧几何 | 一次性重写期望值（字号 15/14、页脚 `NN / MM`、封面 fixture），全量 1,766 项测试回归通过 |
