# UI 字号与层级（v0.7.1 专项）

> 起因：用户实测「右栏的字体比中栏表格的字体还大」「中栏的阶段字体有点小」。
> 这不是审美偏好，是**层级倒置**：辅助信息比主信息更抢眼。本文记录规则与实测值，改 UI 前先读。

## 一、规则（硬约束）

1. **表格正文是主信息**：13px，行高 1.6；表头 12px。
2. **右栏不得大于表格正文**：来源/提醒与表格同为 13px（行高 1.65），只靠颜色与位置区分层级。
3. **阶段/步骤是导航信息**：步骤徽标、流程节点 13px；不允许再用 11px 微标签。
4. **页面标题 20px**；面板标题 16px；表标题 15px；正文 14px；微标签 12px。
5. **字号只能取 token**（`--t2x/--tx/--txs/--ts/--tmd/--tb/--tl`），禁止在组件里写死 px。
6. **中文行高不低于 1.6**（正文/表格/右栏），标题 1.3–1.5。

## 二、实测对照（1512×950，真机 0.7.1）

| 元素 | 调整前 | 调整后 | 说明 |
|---|---|---|---|
| 页面标题（场景名） | 18px / 27 | **20px / 30** | 标题要压得住全页 |
| 步骤徽标（第 6/6 步） | 11px | **13px** | 用户指的「阶段字体太小」 |
| 流程节点（阶段名） | 12px | **13px** | 与步骤徽标同档 |
| 表标题 | 14px | **15px** | 与正文拉开一档 |
| 表格表头 | 11px | **12px** | 仍小于正文 |
| 表格正文 | 12px / 1.7 | **13px / 1.6** | 主信息，加大且更舒展 |
| 右栏来源/提醒 | 14px | **13px / 1.65** | 不再压过表格 |
| 右栏小节标题 | 12px | 13px | 「调研信息来源」等 |

## 三、为什么这样分档

- 13px 是中文表格在 1440–1512 宽下的可读下限；12px 只给表头/徽标。
- 右栏是**辅助**：用户看来源是核对，不是主阅读；与表格同号但用灰色/行距区分，避免"抢戏"。
- 新增 `--tmd: 15px` 是因为原阶在 14 与 16 之间没有档位，表标题只能挤在 14（和正文一样）或 16（像面板标题）。

## 四、防回归

- 单测：`apps/web/src/styles/typography.test.ts`（token 单调、表格≥13、右栏≤表格、表标题/阶段名有独立档位）。
- E2E：`npx playwright test` 45 例（含流程轴/表格/右栏）。
- 手工核对：浏览器 DevTools 选中元素看 computed font-size；右栏 `.det-body` 不应出现横向滚动。

## 五、后续可做（未做）

- 深浅对比度全量审计（当前全部走 token，未发现硬编码颜色）；
- 字号随窗口宽度自适应（当前固定档位，窄屏靠横向滚动）；
- 表格虚拟滚动（行数 > 200 时再评估，当前最大表 118 行）。

# 附：UI 质量与性能专项（v0.7.2）

## 一、对比度（可访问性）

实测发现弱化文字 `--ct3` 原为 `#a1a1aa`，在白底只有 **2.56:1**，侧栏分组标题、流程阶段说明、右栏空态、单元格提示全部不达标（AA 要求 4.5:1）。

| 用途 | 调整前 | 调整后 | 对比度（白底 / 页面底 / 浅灰底） |
|---|---|---|---|
| 弱化文字 `--ct3` | `#a1a1aa` | `#6b6b74` | **5.28 / 5.05 / 4.80** |

全部界面页（工作台 / 资料库 / 设置）复测：**0 处文字对比度不达标**。

## 二、可点区域

| 控件 | 调整前高度 | 调整后 | 原因 |
|---|---|---|---|
| 流程阶段节点 | 19px | **24px** | 阶段名是主要导航，点不中会误以为“锁死” |
| 行内小按钮（重新生成等） | 20px | **24px** | 桌面端最小可点区域 |

## 三、动效与细节

- 5 处 `transition: all` 改为只过渡颜色/背景/边框/透明度，避免无意中过渡布局属性；
- 表格数字启用 `font-variant-numeric: tabular-nums`，价格/数量/日期跨行对齐；
- 选中文本使用品牌浅色，不再出现系统默认蓝；
- 侧栏被省略号截断的场景名补 `title`，悬停可看全名；
- 键盘 Tab 实测：所有可聚焦控件都有 2px 可见焦点环（含隐藏的「⋯」按钮）。

## 四、性能实测（0.7.2，Apple Silicon，1512×950）

| 指标 | 实测 | 说明 |
|---|---|---|
| 首屏 FCP | **40–44ms** | 本地构建产物，系统字体，无网络字体 |
| 外壳可交互 | **46ms** | `.shell` 可见 |
| 切换流程阶段（JS 渲染） | **52ms** | 服务端数据 3ms，端到端 < 100ms |
| 切换资料库页签（JS 渲染） | **65ms** | 单次 API 3ms |
| 拖拽列宽 | **60fps**，最大帧 17ms | 33 帧无 >32ms 卡顿 |
| 长任务（longtask） | **0** | 启动、切步、切页签全程无 >50ms 长任务 |
| 页内横向溢出 | **0** | side/main/det 三栏均无 |

结论：当前 UI 的瓶颈不在渲染，交互延迟主要来自服务端取数（已 <5ms，本地库）。未引入虚拟滚动/代码分割——现有最大表 44 行、资料库单页 38 行，收益小于复杂度。
