# 场景通 桌面版使用说明

> 适用版本：0.1.0 起（Electron 桌面壳）。分发方式：GitHub Release / 百度网盘，**免签名**安装包。

## 一、它是什么

桌面版 = 把一个 **Electron 窗口** 和一份**只在本机运行的本地服务**打成一个应用：

- 应用启动时自己拉起本地服务（**运行时现选空闲端口**，不写死 46172，所以不会和别的程序撞端口）；
- 服务只监听 `127.0.0.1`，**不对局域网开放**；
- 你的数据（数据库、交付物、导出文件）全部落在**系统应用数据目录**，不在安装目录、也不在你当前的工作目录；
- 模型调用是**直连 OpenAI 兼容接口**，不需要额外装 Node、不需要装 DeepSeek Harness。

| 平台 | 应用数据目录 |
|---|---|
| macOS | `~/Library/Application Support/场景通/` |
| Windows | `%APPDATA%\场景通\`（即 `C:\Users\<你>\AppData\Roaming\场景通\`） |

里面的结构：

```
data/scene.db          ← 业务数据库（场景、信息表、材料索引）
data/deliverables/     ← 生成的两份交付物（Markdown）
exports/               ← 导出的 Word / PPT / Markdown
logs/server.log        ← 本地服务日志（出问题先看这个）
```

## 二、安装与首次打开

### macOS

1. 下载对应芯片的安装包：**Apple 芯片（M 系列）选 `…-mac-arm64.dmg`**，Intel 选 `…-mac-x64.dmg`；
2. 打开 dmg，把「场景通」拖进「应用程序」；
3. **首次打开要右键（或按住 Control 点）→「打开」→ 再点「打开」**。
   因为安装包没有 Apple 开发者签名，直接双击会被 Gatekeeper 拦下说「无法验证开发者」。
4. 如果还是被拦，终端执行一次即可（把应用装好后跑）：

```bash
xattr -dr com.apple.quarantine /Applications/场景通.app
```

> 为什么不做签名：签名与公证需要 Apple 开发者账号（每年 99 美元）。内网/小范围分发用右键打开即可；如果你希望彻底去掉这个提示，我可以再加签名与公证流程（需要你的证书）。

### Windows

1. 下载 `…-win-x64-安装版.exe`（会装到本用户目录，不需要管理员权限）或 `…-win-x64-免安装版.exe`（绿色包，双击即用）；
2. 运行时若出现蓝色 **SmartScreen** 提示，点「**更多信息**」→「**仍要运行**」；
3. 安装版会创建桌面与开始菜单快捷方式。

## 三、首次配置（必做一次）

应用启动后左侧点「**设置**」→ 在「模型配置」里：

| 字段 | 填什么 |
|---|---|
| 名称 | 随便起，例如 `公司网关`、`DeepSeek` |
| 链接 | OpenAI 兼容端点，例如 `https://api.deepseek.com/v1`（自定义网关就填它的 `/v1`） |
| API Key | 你的密钥（**只存在本机，不回传到界面**，界面上只显示掩码） |
| 模型 | 可点「**获取模型列表**」自动发现后选用，或手敲模型 ID |

点「**测试连接**」，显示「模型可用 · 生成往返 xxx ms」即配置成功，然后把它设为默认模型。

> 密钥保存在应用数据目录的供应商登记文件里（权限 `0600`，仅本用户可读）。**默认就用这个方式**——
> 不碰系统钥匙串，所以不会弹系统授权框、也不会问你登录密码。想要"文件被拷走也解不开"的强度，
> 见下面「密钥是怎么存的」一节的 `SCENE_KEYCHAIN_PROTECTION=1`。

## 四、日常使用

- **新建场景**：左侧「新建」，只输名称；场景本体在「场景定义」对话里聊清楚（那是唯一一处对话界面）。
- **导出**：交付物面板里导出 Word / PPT / Markdown，文件落在应用数据目录的 `exports/`。
  菜单「**文件 → 打开导出目录**」可以直接在访达 / 资源管理器里打开它。
- **看数据在哪**：菜单「**文件 → 打开数据目录**」。
- **本地服务地址**：菜单「**帮助 → 本地服务地址**」会显示当前端口与数据目录（端口每次启动都可能不同，属正常）。
- **重开应用**：只允许一个实例，重复启动只会把已有窗口抬到前面。

### 密钥是怎么存的（重要）

**默认：密钥明文存在应用数据目录里，文件权限 0600（只有你自己能读）。**

这是刻意的默认值。桌面版是**免签名**分发的，macOS 没法把「始终允许」稳定记住——
一旦用系统钥匙串，每次启动都会弹授权框、**要你输登录密码**，还会卡在启动页等它。
你反馈过「能不能不要老是输密码」，所以钥匙串保护改成**显式开启**：

```bash
# 想要"连文件被拷走也解不开"的强度时，显式打开（会带来系统授权提示）
SCENE_KEYCHAIN_PROTECTION=1 open -a 场景通
```

开启后：首次运行会在系统钥匙串里放一把随机主密钥（macOS 的「钥匙串访问」里名为 `场景通 Safe Storage`，
Windows 走 DPAPI），再用它对登记表里的 Key 做 AES-256-GCM 加密落盘；单独把数据目录拷到别的机器
是解不开的。代价就是要输密码、每次覆盖安装后可能再问一次。

无论开不开：
- 想彻底清掉密钥：在应用内「设置 → 模型配置」删除该供应商即可。
- 换电脑：新机器上重新录入 Key。
- 用「终端里跑 node 起服务」去开桌面版的数据目录，是读不到加密密钥的（设计如此，日志会写明原因）。

## 五、出问题了怎么办

| 现象 | 处理 |
|---|---|
| 提示「没能启动本地服务」 | 菜单打开数据目录 → `logs/server.log`，把最后几十行发给开发者 |
| 界面卡住不动 | 菜单「视图 → 强制重新加载」；仍不行就退出重开（数据不会丢） |
| 模型测试连接失败 | 检查链接是否带 `/v1`、Key 是否过期、公司网络是否需要代理 |
| 想换台电脑用 | 拷走应用数据目录即可（`data/` + `exports/`），装好应用后放到同样的位置。默认配置下 Key 跟着文件走；**若开过钥匙串保护**，则新机器上要在设置页重新录入 Key |
| 换电脑后提示密钥读不到 | 只会在你开过钥匙串保护时出现：密钥由原机器的钥匙串保护，新机器解不开。在设置页重新填一次即可（旧密文会被覆盖） |
| 打包时中途报 TLS/网络错误 | 是下载 Electron/打包工具时网络瞬断，重跑一次即可（真实遇到过一次，第二次直接过） |
| 一直显示「分析中」，也没有内容，点按钮没反应 | 分析可能**早已跑完**（0.1.2 起界面会自己收口，不再钉住）：先按 **⌘R**（菜单「视图 → 重新加载」）刷新看结果；若仍显示分析中，打开 `logs/server.log` 看有没有 `incoming request`（0.1.2 起会记录请求），把最后几行发我 |
| 点「整理成定义」后场景概述还是空的 | 0.1.1 起会**直接告诉你原因**（不再静默空白）：界面显示「整理失败：…」，同时 `logs/server.log` 里记下失败原因与模型原文片段。多数情况是模型 ID 写错或模型不匹配，去「设置 → 模型配置」确认（DeepSeek 可用 `deepseek-chat` / `deepseek-flash` / `deepseek-reasoner`），改完再点一次即可 |
| 老让我输登录密码 | 默认配置**不会**出现（不用钥匙串）。若你显式开过 `SCENE_KEYCHAIN_PROTECTION=1`：那是 macOS 在问钥匙串权限，输密码或点「拒绝」都行——拒绝后应用照常工作，Key 按明文 0600 存 |
| 启动后一直停在「正在启动」 | 大概率是有个系统弹窗等你点（钥匙串授权最常见）。切到应用窗口处理掉它；也可直接退出，不带 `SCENE_KEYCHAIN_PROTECTION` 重开 |

## 六、开发者：怎么构建与发布

```bash
pnpm install
pnpm build                      # 契约/领域/基础设施/服务端/前端
pnpm run desktop:runtime        # 装配运行时（deploy --node-linker=hoisted + 下 Electron ABI 预编译）
node apps/desktop/scripts/smoke.mjs            # 桌面壳冒烟：真启动应用、真拉本地服务、验数据库真建出来
pnpm --filter @scene/desktop run verify:settings   # 验「应用内配置模型」：能保存、密钥落 0600、不回显
pnpm run desktop:dev            # 本地起桌面版（开发用；带开发者工具）
pnpm run desktop:pack:mac       # 出 mac 安装包（宿主架构；交叉用 --filter @scene/desktop run pack:mac:x64）
pnpm --filter @scene/desktop run smoke:packaged      # 对打包产物做冒烟（内含运行时一致性校验，强烈建议每次分发前跑）
pnpm --filter @scene/desktop run verify:runtime      # 单独跑运行时一致性校验（包内外逐字节比对）
pnpm --filter @scene/desktop run verify:settings     # 对打包产物验「应用内配置模型」
pnpm run desktop:pack:win       # 出 win 安装包（安装版 + 免安装版）
```

**发布**：推一个 tag（如 `git tag v0.1.0 && git push --tags`）→ GitHub Actions（`.github/workflows/desktop.yml`）会在 macOS 与 Windows 机器上各自构建、各自跑冒烟，然后把安装包附到 Release。把 Release 里的文件转存到百度网盘即可分发给不用 GitHub 的人。

### 必须知道的坑（都真实踩过）

1. **`better-sqlite3` 是原生模块，ABI 必须匹配运行时。** 桌面版里服务端跑在 **Electron 自带的 Node** 里（`ELECTRON_RUN_AS_NODE=1`，这样安装包不用背 Node），所以需要一份 **Electron ABI** 的二进制——即 `apps/desktop/runtime/server`（由 `desktop:runtime` 生成，不入库）。
   **千万不要在仓库根目录原地重建**：那份是给系统 Node 用的，重建后本机 `npm start` 的服务和 `pnpm test` 会一起报 ABI 不匹配。
   2026-10-12 就发生过一次（`@electron/rebuild` 顺着 pnpm 的符号链接改到了仓库那份，把开发环境弄坏），所以现在有两条硬措施：
   - **用预编译、不编译**：`prebuild-install --runtime=electron` 直接下预编译包，不需要 Xcode / VS 工具链，CI 也更快；
   - **装配脚本自带围栏**：所有删除动作只允许落在 `apps/desktop/runtime` 与系统临时目录内，越界直接失败；收尾还会自检「仓库里给 Node 用的那份仍可用」。
   Electron 与 better-sqlite3 的版本是**配对钉死**的：当前 Electron 36.x（ABI 135）对应 better-sqlite3 11.10.0 已发布的预编译。升级任何一方前，先确认这组 ABI 有预编译（见 `prepare-server.mjs` 头注释里的链接）。
2. **`ELECTRON_RUN_AS_NODE` 会让应用起不来。** 这个变量若出现在环境里，Electron 会以"纯 Node"方式跑主进程，`require("electron")` 只返回一个路径字符串，应用一启动就崩。应用里加了防呆提示；用脚本拉起时记得清掉（`env -u ELECTRON_RUN_AS_NODE …`）。
3. **打包产物必须单独验一遍，而且要和架构配对。** 两类问题只在真产物上暴露：① electron-builder 会把运行时里的 `node_modules` 当"依赖"裁掉（现已改用 `files` + `asarUnpack` 规避）；② 原生模块是**架构相关**的——在 arm64 机器上交叉打 x64 包，塞进去的还是 arm64 二进制，用户装上就起不来。所以：每个架构在自己的机器上打包（CI 矩阵：`macos-14` / `macos-13` / `windows-latest`），并且打完跑一次 `pnpm --filter @scene/desktop run smoke:packaged`（在**未压缩的打包产物**上做冒烟）。
4. **分发前确认没带上开发数据。** `prepare-server.mjs` 会剪掉 deploy 产物里的 `data/`，否则会把开发机上的真实数据库打进安装包。
5. **出包前必须清掉上一次的产物目录。** `electron-builder --dir` 往已存在的目录里写时**不会清** `app.asar.unpacked/`，
   而 Electron 解析被 unpack 的路径时优先用那份副本——于是"新壳 + 旧运行时"会**静默**成立：代码明明改了、装出来的应用行为还是老的，
   而且不报错（2026-10-12 真实踩过：密钥加密已经写进运行时，打包产物里还是旧的 `provider-store.js`，查了半天）。
   现在两道闸：打包命令里先跑 `scripts/clean-release.mjs` 清目标目录；`smoke:packaged` 开跑前先用
   `scripts/verify-runtime.mjs` 逐字节比对包里运行时与刚装配的那份，不一致直接失败。

## 七、离线/内网分发的注意事项

- 安装包**不含**模型端点与密钥，也不含任何场景数据——拿到包的人是"干净"的，首次配置后才能用。
- 应用不需要联网才能启动（只在调用模型时需要能访问你配置的端点）。
- 百度网盘分享时建议连同本文件的「二、安装与首次打开」一起发给对方，macOS 的右键打开那一步最容易卡住人。
