# 01_cover

场景通不是一个聊天框。它是把售前调研这件事，从找资料到出方案，做成一条可交付的工作流。接下来用几分钟，看看它怎么跑完一个场景。

# 02_problem

一个场景卡住，往往不是方案写不出来，而是调研阶段材料太散、维度容易漏、来源又说不清。找资料要几天，补齐合规和竞争维度再花几天，最后方案里的数字还未必敢拍。一来一回，一到两周就过去了。

# 03_workflow

场景通把这段调研拆成六步：场景定义、认识场景、理解商业、能力匹配、方案与实现、交付物。每一步都有固定的表和产物，AI 先跑一遍，人再做校对和判断。它不是让模型自由发挥，而是把过程拆成可检查的中间结果。

# 04_library

产品资料只入一次库。产品清单、规格书、能力、边界、案例，AI 解析成结构化条目，统一维护。新建场景时直接引用，不用每次重新收集，也不容易用错版本。

# 05_definition

新建场景，只输一个名字。AI 先讲清这类场景大概是什么样，再问两三个关键问题：客户是谁、覆盖什么。用户说个大概，它整理成场景定义和边界。不是先让用户填二十六张表，而是 AI 先理解，用户再确认。

# 06_analysis

接下来，AI 按六步逐项调研、逐张填表。表格不是让用户从零填，是 AI 先给初稿，人再逐格改。每条结论都能点开来源，右栏有来源标题、日期、权威性和证据等级；查不到就写未知，不拿模型知识冒充客户事实。

# 07_edit

发现哪条不对，不用找单元格。右栏直接说：把这条改成按会议室逐间推进。AI 调工具改表，中栏马上更新。一句话改一行，也能让它补一条来源，改完继续追问，不用切页面。

# 08_deliverables

最后，解决方案和 PPT 大纲同一次生成。解决方案有章节、有来源、有边界；大纲按正文展开，页标题和要点都能改。确认后直接导出 Word 或 PPT，拿去汇报，不用再花时间二次整理。

# 09_value

所以价值不只是快。第一，调研周期从一到两周压到一到两天；第二，每条结论有来源，方案站得住；第三，产品资料和场景资产越用越厚，经验留在团队，而不是个人脑子里。去掉 AI，产品只剩空表和空文档。

# 10_architecture

最后补充一句。场景通本身是一个方案生成工具，但它验证了一套更通用的智能体参考架构：DSH 提供运行时，文档解析、模型、Word/PPT 生成是工具，六步方法和二十六张表是场景调研这一种工作的方法层。换一种工作类型，比如投标文件评审、客户需求分析，运行时和工具链不变，重写方法、表结构和输出契约，就能把输入、方法、工具、输出串成可复用的组织能力。
