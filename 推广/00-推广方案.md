## 一、一句话说清这个系列

**给谁看**：解决方案架构师、售前、工业物联网/边缘计算方向的技术负责人，以及正在自建 AI Agent 工作台的工程师。
**解决什么**：让他们相信"场景调研这件事可以被结构化、可追溯、可复现地自动化"，并且**当天就能装上用**。
**不打什么**：不做"AI 万能"式宣传，不承诺替代人做决策，不吹模型能力。

### 双平台分工（同一选题、两种写法）

| | B 站（口播视频） | CSDN（技术长文） |
|---|---|---|
| 长度 | 8–15 分钟，250–400 字/页 × 8–12 页 | 8000–15000 字 |
| 侧重 | 场景代入、机制讲透、一页一个点 | 架构、契约、代码、可复制的实现 |
| 语气 | 口语、类比、设问推进、带个人风格 | 工程判断、有取舍、给配置与命令 |
| 技术深度 | 讲"为什么这么做"，省略分支细节 | 讲"怎么做到的"，给源码速览与验收口径 |
| 推广落点 | 结尾 30 秒：这东西解决你哪个痛 + 怎么拿 | 文末行动清单 + 系列导航 + 获取方式 |
| 转化路径 | 简介/置顶评论 → 获取通道 → 交流群 | 文末 CTA → 获取通道 → 技术反馈 |

**共同铁律**：每条技术断言必须有依据；demo 数据全部虚构（见第八章）；不出现真实公司名、真实产品型号、API Key、内网地址。

### 演示品类：工业物联网 / OpenHarmony（要显性讲出来）

老李自己的技术背景是工业物联网与 OpenHarmony 落地，所以这套 demo 就选这个品类——**虚构公司"云枢智控"做工业边缘控制器与工业网关，边缘控制器的操作系统是"云枢 OS（基于 OpenHarmony 5.0）"**。

这个选择不是贴标签，它在内容里有三处实打实的作用：

1. **门槛问题最典型**：这个品类里"能不能进"卡的不是功能，而是认证、协议、数据出域、交付窗口——正好是这套工具的主场。
2. **能力最容易被高估**：能力清单写得满，一到具体场景就露馅（参数可选、某型号没 NPU、老机取数还没勘察）。工具的价值就是把这类话挑明白。
3. **OpenHarmony 这条事实是带出处的**：它在资料库里是 M2 规格书的一行（`软件 / 操作系统 / 云枢 OS（基于 OpenHarmony 5.0）`，`measured = 宣称`），出处标注 `云枢智控-产品与能力白皮书.docx:表格3`，权威性 T3、证据级 B，选中即见。配图 `期1-定位/04b-产品资料库-M2-操作系统-OpenHarmony.png` 一图同屏。

> **讲这条的正确姿势**：不要把 OpenHarmony 讲成"所以先进"。要讲成"连'操作系统基于 OpenHarmony 5.0'这种事实都是带出处的，能点开看它出自哪张表，也能一眼看到它只是'宣称'不是'实测'"。卖点是**可核查**，不是鸿蒙本身。

## 二、内容主线（5 期叙事弧）

一条从"痛"到"信"到"用"的弧线，每期只保**一个主论点**：

```
① 痛在哪    产品没问题、方案也合理，项目却做不成 → 做方案前先把场景与行业查透（全片无产品）
      ↓
② 用 AI 做    承接①：如何用 AI 快速深入了解一个行业和场景（产品首次亮相 + 端到端实战）
      ↓
③ 凭什么信  架构分工：判定不交给大模型，落确定性层（立信任）
      ↓
④ 怎么防胡  来源溯源 + 生成后三问自检（解决"AI 写的不敢用"）
      ↓
⑤ 怎么上手  本地部署、装完即用、可二次开发（收口获客）
```

先给痛（①），再给结果（②），再给原理（③④），最后给行动（⑤）。B 站按此顺序；CSDN 把③④提前也成立，因为技术读者先关心"你怎么做到的"。

### 可放心引用的实现细节（已核实到代码行）

- **入库格式**：`.pdf .docx .xlsx .pptx` 四种；PDF 扫描件按"去空白文本 < 10 字符且页数 > 0"识别，走 macOS Vision OCR（`scripts/ocr_pdf.py`，超时 180s）
- **全文索引**：`source_fts` 用 FTS5 + `trigram` 分词，INSERT/UPDATE 触发器同步；反查时只用 MATCH 短语查**该出处那一页**，最短 3 字符
- **来源格式**：`文件名:页码` 为必填，缺失或无依据则条目作废
- **生成后三问**：第 1 轮全量**只报告**（不改）→ 第 2 轮**只改被点名的行** → 第 3 轮**复查仍存疑的行**；每批 ≤ 60 行、单轮 180s、总上限 10 分钟
- **G-R9 确定性判定**：中栏夹带出处（7 条正则，命中即判定）、中栏 > 60 字（表1-1 除外）；三轮后由确定性逻辑把引用搬进右栏，正文一字不删
- **G-R10 确定性判定**：写"不能碰"且核实结论为"无法核实/有反证"即判硬伤；跨表比对能力底账（只比能力名、不比限制条件）
- **LLM 不进判定路径**：来源权威性（T1–T4）与证据级（A–D）由服务端函数计算后才入库，模型自封的核实状态会被剥掉；模型可改的只有内容列与核实列，且**不许把状态升为"已核实"**
- **失效重算**：单元格编辑 → 反查依赖表 → 标 `is_stale`；重算只删本次确实产出的表，零产出不清库、半张表不覆盖
- **交付物篇幅门禁**：解决方案 1200–4500 字，建设工作方案 2000–5000 字

## 十二、实测发现：模型会在行业常识列带出真实厂商名（必读）

跑完演示场景后做全库扫描，发现一个**必须在上线前处理**的问题：

> 本节以下出现的真实厂商名，只是「哪些名字必须被替换掉」的审计清单，**不属于任何对外内容**。

| 项 | 情况 |
|---|---|
| 现象 | 「门槛与合规」的否决方、「上游供给格局」「竞争对手对照」等**需要行业常识**的列里，模型写入了真实厂商名 |
| 命中规模 | 68 个真实厂商名、216 行次（西门子 22、树根互联 16、罗克韦尔 11、蘑菇物联 10、力劲 9、伊之密 9…） |
| 根因 | 上传材料本身是干净的（已做 555 条黑名单扫描，0 命中）。这些名字来自**模型自身的行业知识**，不是来自材料 |
| 影响 | 直接截图发出去就违反隐私与合规红线；且与演示世界的虚构品牌不自洽 |
| 处理 | 已写 `推广/素材/.tools/desensitize.py`，把 68 个真实厂商名整体映射为虚构厂商（含 `中控(?!室)` 这类必须用正则的特例），对全库所有文本列做替换；替换后重扫为 0 命中 |

**这条对内容侧有两个直接影响**：

1. **所有截图必须在脱敏之后重拍**，不能用脱敏前的图。
2. **它本身就是一个值得写进文案的诚实点**——第 4 期或第 5 期加一句"工具能约束措辞与出处，但『行业通例』那一列是模型知识，对外发布前仍需人工过一遍脱敏"。这比假装它什么都能兜住更可信。

> 长期建议（不在本次发布范围）：产品侧加一个「对外发布脱敏」开关，对指定列做实体黑名单替换。已记入待办，本次不做。
