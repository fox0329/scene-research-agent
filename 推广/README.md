## 五、两份「成稿」素材是怎么出来的

白皮书与产品介绍 PPT 不是用 python-docx / python-pptx 直接拼的——那样出来的是通用排版，
和产品导出交付物的观感对不上。这两份改走**产品自己的输出链路**，观感与 `导出 Word 文档` /
`导出 PPT 文档` 按钮的产物同源：

```
云枢智控-产品与能力白皮书.md  ──build-whitepaper.mjs──▶  @scene/infra docx-report
   （内容源，从旧版 docx 逐块抽出）                      （A4 / 宋体 / 章节自动编号 / TOC / 页眉页脚 / Table Grid / 表标题）
                                                        └▶ 云枢智控-产品与能力白皮书.docx

产品介绍-大纲.json           ──build-deck.mjs──────────▶  @scene/infra ppt-svg（七种版式 + B站蓝色令牌）
   （9 页大纲，数字逐条对得上白皮书）                      └▶ ppt-master finalize_svg.py（嵌真图标）
                                                        └▶ ppt-master svg_to_pptx.py --no-compat -f ppt169
                                                        └▶ 云枢智控-产品介绍.pptx
```

重建（顺序无所谓，两者互不依赖）：

```bash
node 推广/素材/.tools/build-whitepaper.mjs          # 白皮书
node 推广/素材/.tools/build-deck.mjs --emit         # PPT（不带 --emit 只校验不转档）
node 推广/素材/.tools/preview-deck.mjs              # PPT 每页截 PNG，人眼复核版式
```

两道 PPT 门禁（`checkPptOutlineQuality` 大纲八条 + `checkPptDeck` 版面）目前均为 **0 问题**；
Word 侧有 1 条单测守着表标题样式。产出的中间物留在 `推广/素材/demo资料/.deck-build/`，可复查。

> 唯一一处对产品渲染结果的改写：PPT 页脚被产品硬编码成「场景通 · 场景名」（导出交付物时这是对的），
> 但这份 PPT 是**演示世界里虚构厂商自己的产品介绍**，是喂给场景通的输入材料，印上工具名会让虚构设定穿帮。
> `build-deck.mjs` 只摘掉页脚前缀，页面其余部分一字不动。
